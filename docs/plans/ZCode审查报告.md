## 2. 仍未闭环的冻结阻断项

### 2.1 命令族三处两个版本（P0-1 残留，必须修订）

`006 design.md:577` 已冻结 10 命令族（含 `report-failure`），但实现依据 `006 impl.md:318` 与接入规范 `README.md:25` 仍写旧的 9 命令族，且 README 仍用"拟交付"措辞（design 已改"冻结"）。照 impl/README 实施会再次漏掉 `report-failure`，P0-1 的修复只落在三处中的一处，并新引入"设计与实现/规范不一致"。修复为两行文本的机械对齐。

### 2.2 提示词内容清单仍未统一（第一轮 P1-3）

`006 design.md:460` 要求提示词"固定包含……CLI/Runtime 默认路径"，而被指定为权威的模板（`README.md:41-73`）与 `004 design.md:18`、`004 impl.md:5` 均无该项，AI-PKG012 断言也不含。Codex 报告声称"统一提示词中的 SKILL.md、manifest.json、固定版本和 /mcp 地址"，实际只改了邀请主体，地址清单分歧原样保留。二选一即可：模板补一项明确的 CLI/Runtime 安装入口，或从 design §9.3 删除该措辞并让 AI-PKG012 与最终模板逐项对齐。

### 2.3 基础地址规则空引用未删除（第一轮 P1-4）

`004 design.md:18` 与 `004 impl.md:5` 的"统一站点/外部基础地址规则"原样保留，docs 全库仍无定义，代码亦无子路径能力（`vite.config.ts` `base:'/'`、服务端无 `UsePathBase`）。Codex 报告声称"删除……空引用，改为同源根路径规则，并明确当前服务外部地址"，与文档现状不符——这是本次核实中第二处"声明已修复但未修复"的条目。处理方式：删除两处短语并写明"首版仅支持根路径同源部署，提示词地址一律由当前页面 origin 推导"，或先在 002/004 定义规则再引用。

## 5. 冻结判断

**结论：完成三项机械修订后即可冻结并启动实施；当前瞬间状态尚不建议直接冻结。**

与第一轮相比，冻结门槛已从"3 项 P0 + 10 项 P1 的设计缺口"降低到"3 处纯文本机械修订"：

1. 命令族对齐：`006 impl.md:318`、`README.md:25` 补 `report-failure`（并同步"冻结"措辞与 retry 语义一句）——对应 2.1；
2. 提示词清单二选一对齐：006 §9.3 与模板/AI-PKG012 一致——对应 2.2；
3. 删除或落实基础地址规则空引用：`004 design.md:18`、`004 impl.md:5`——对应 2.3。

三项均为无设计决策的文本修订，完成后无需再次全量审查，可直接冻结。冻结对象是"技能 + CLI/Runtime + MCP 双通道 + 同版本发布包"的设计契约；实现完成仍须按 006 第 8 节、testPlan 第 20 节（AI-PKG001~015）及 007/008 回归矩阵验收后方可宣布产品完成。

**冻结后可立即并行启动**：`release.json` 与 `publish.ps1` 聚合改造、`Client/rtm-agent/` 项目骨架（15.1.1 契约已冻结，可直接落地）、`Program.cs` 静态映射与 fallback 排除（按 `Server/design.md`）、`.gitignore` 状态目录规则、服务端 `notifications/initialized` 500 修复、既有客户端测试断言的改写准备。
