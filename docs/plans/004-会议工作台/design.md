# 会议工作台主题总体设计

## 1. 文档定位

本文是“会议工作台”主题的总体设计，负责确定本主题的目标、范围、跨端会议契约、子文档分工、前置依赖和完成门槛。服务端、客户端、模块、页面和组件的具体设计分别由本目录下的子文档负责。本目录编号为 004，对应[总体设计](../001-总体计划/design.md)中的“主题三：会议工作台”。

本主题的产品依据为[圆桌会议网站需求](../../需求分析/圆桌会议网站需求.md)和[圆桌会议网站总体设计](../001-总体计划/design.md)。已经确认的产品定位是：会议是创建后立即可用的临时圆桌会话，不是预约会议；会议及参与关系长期保留，直到创建者主动删除。

## 2. 主题目标

本主题建立人类用户进入圆桌会议核心业务的第一个完整闭环。主题完成后，已登录用户必须能够：

1. 创建会议并立即进入该会议。
2. 作为创建者查看会议码并将其复制给其他参与者。
3. 使用会议码和会议内显示名称直接加入会议，不需要创建者审批。
4. 查看自己创建或曾经加入的全部会议。
5. 在同一工作台内切换多个会议。
6. 查看当前会议的基本信息和静态参与者列表。
7. 刷新页面或更换设备后根据账号恢复已有会议参与身份。
8. 由创建者删除会议，使旧会议码和所有既有访问立即失效。

## 3. 产品语义

### 3.1 创建即运行

会议创建成功时即成为可访问、可加入的群聊空间。首版没有草稿、预约、待开始、进行中或已结束等状态，也没有开始会议和结束会议操作。创建表单只包含必填会议名称和可选讨论主题或背景说明，不设置人数上限、会议密码或有效期。

### 3.2 长期参与关系

创建者创建会议时自动成为一个人类参与者。其他人类账号首次使用会议码加入后，参与关系和会议内显示名称持续保留。关闭页面、切换会议、退出登录、网络中断或所有人暂时离线都不等于退出会议。首版不提供主动退出会议。

### 3.3 会议码

会议码是用于发现并申请加入会议的可分享邀请凭证，不是读取会议内容的长期授权令牌。人类加入后，后续访问依据稳定账号 `UserId` 与参与者关系授权，不要求再次提交会议码。会议码在会议存续期间不变，不允许重新生成；会议删除后永久失效。

### 3.4 会议内显示名称

人类账号身份和会议内显示名称相互分离。首次加入时默认使用账号昵称，用户可以改为仅属于该会议的名称；加入成功后首版不可修改。同一会议内所有人类和未来 AI 参与者共享统一名称空间，名称比较使用去除首尾空格、Unicode NFC 和不区分大小写的规范化结果。

## 4. 本次实施范围

### 4.1 必须实现

- 登录后会议工作台和多会议导航。
- 创建会议、生成随机 GUID 会议码、创建者自动入会。
- 通过会议码直接加入，不提供审批流程。
- 首次加入时确认或修改会议内显示名称。
- 当前用户会议列表和多个会议切换。
- 会议基本信息，以及仅创建者可用的会议码展示和复制。
- 人类参与者静态列表，以及为后续 AI 类型保留稳定参与者类型契约。
- 已有参与身份恢复，重复加入保持幂等。
- 创建者删除会议、删除访问屏障、会议码失效和本主题已有从属数据清理。
- 随机 GUID 会议码、加入限流、日志脱敏和成员访问授权。

### 4.2 明确不在本主题实现

- 消息历史、消息输入、文本发送、`@` 提及和系统消息。
- 浏览器实时同步、在线或离线状态、连接恢复和未读状态。
- AI Agent 通过 MCP 加入、AI 连接状态、上下文或回复任务。
- 会议开始、结束、预约、有效期、人数上限和会议密码。
- 加入审批、邀请成员账号、公开会议、会议搜索和会议目录。
- 主动退出会议、踢出、禁言、转让创建者和修改参与者名称。
- 修改会议名称或背景、重新生成会议码和归档会议。
- 删除会议以外的单项清理、恢复已删除会议和回收站。

工作台在本主题提供稳定的消息区域插槽和空状态，但不能用模拟消息或不可用输入框冒充主题四功能。

## 5. 跨端核心契约

### 5.1 会议

会议至少包含以下业务信息：

- `MeetingId`：服务端生成的稳定 `Guid`。
- `Name`：规范化后的会议名称。
- `Description`：可选的讨论主题或背景说明。
- `MeetingCode`：创建会议时服务端生成的新随机 `Guid`，作为长期不变的加入凭证；数据库以 Guid 明文持久化，只有创建响应和创建者邀请信息响应向客户端返回。
- `CreatorUserId`：创建者账号稳定标识。
- `CreatedAt`：服务端 `TimeProvider` 产生的 UTC `DateTimeOffset` 创建时间。
- `LifecycleState`：服务端删除收敛所需的 `Active | Deleting`；客户端正常业务只展示 Active 会议。

会议没有正式开始时间、结束时间、参与人数限制、密码和到期时间。

创建命令额外携带客户端生成的 `CreationRequestId`。它不属于会议公开业务信息，只由最小创建回执保存，用于断网重试防止重复创建。会议删除后回执转为 Deleted，旧请求 ID 不能重新创建会议。

### 5.2 人类会议参与者

人类参与者至少包含：

- `ParticipantId`：稳定 `Guid`，后续消息发送者和实时状态引用该标识。
- `MeetingId`：所属会议。
- `UserId`：所属人类账号。
- `ParticipantType`：本主题创建的数据固定为 `Human`；后续主题扩展 `Agent`，不另建相互冲突的参与者模型。
- `DisplayName`：保存的会议内显示名称。
- `NormalizedDisplayName`：统一名称比较值。
- `JoinedAt`：服务端 `TimeProvider` 产生的 UTC `DateTimeOffset` 首次加入时间。

同一会议内同一 `UserId` 只能对应一个人类参与者；同一会议内 `NormalizedDisplayName` 对所有参与者类型统一唯一。

### 5.3 工作台读模型

工作台使用面向界面的读模型，不直接暴露领域实体：

- 会议列表项：会议标识、名称、当前用户显示名称、是否为创建者、首次加入时间。
- 当前会议详情：会议基本信息、当前用户参与者身份、是否可删除、是否可管理邀请和参与者列表；不包含会议码。
- 创建者邀请信息：会议标识和可见会议码；普通成员不能取得该读模型。
- 参与者摘要：参与者标识、显示名称、类型、是否当前用户、是否创建者、加入时间。

本主题不返回在线状态、消息摘要、最后消息时间、未读数量或 AI 处理状态。

## 6. 权限边界

1. 所有浏览器会议 API 都必须通过主题二的 Cookie 认证。
2. 只有会议参与者可以在加入后读取会议详情和参与者列表。
3. 只有创建者可以读取会议码和删除会议。
4. 会议码只允许用于加入入口，不能绕过参与者授权直接读取详情。
5. 会议列表只能返回当前账号已经拥有参与者关系的会议。
6. 会议处于 `Deleting` 后，所有会议读取、加入和写入入口统一按不可访问处理。

对非成员请求不泄露会议是否存在、创建者是谁或参与者名称。成员范围外访问会议详情或删除入口统一使用 `404 meeting_not_found`，而不是通过 `403` 暴露资源存在性。邀请入口对任何非创建者统一返回 `404`，避免暴露创建者身份；删除入口中，已是成员但不是创建者的账号已经知道会议存在，因此返回 `403 meeting_creator_required` 提供可理解的权限提示。

## 7. 关键业务流程

### 7.1 创建会议

1. 已登录用户打开工作台并选择创建会议。
2. 输入会议名称和可选背景说明。
3. 服务端读取当前账号昵称，规范化并作为创建者的会议内显示名称。
4. 服务端创建会议、生成会议码、创建人类参与者，并在同一工作单元提交。
5. 客户端刷新会议列表并导航到新会议。
6. 工作台向创建者提供会议码邀请操作，显示参与者列表和待主题四接入的消息区空状态。

若账号昵称与输入约束不兼容，创建请求返回明确字段错误，不创建半成品会议。账号主题已将昵称限制为 64 个字符，因此主题三采用同一显示名称上限。

### 7.2 首次加入会议

1. 已登录用户输入会议码。
2. 客户端调用加入预检，只返回 `meetingId`、会议名称、可选背景、默认显示名称，以及当前账号是否已经加入和已有显示名称；不返回会议码或参与者列表。
3. 用户确认或修改本次会议的显示名称。
4. 服务端重新验证会议码、会议状态和名称唯一性，创建参与者关系。
5. 客户端刷新会议列表并导航到已加入会议。

预检结果不是授权承诺。最终加入必须在提交时再次验证全部规则，不能依赖客户端持有的预检状态。

### 7.3 重复加入和身份恢复

- 已经加入过会议的人类再次输入同一会议码时，服务端按 `MeetingId + UserId` 恢复原参与者并返回成功，不创建第二条参与者记录，也不修改已有显示名称。
- 从会议列表或深链接打开会议时，不需要会议码，服务端根据当前账号的参与者关系授权。
- 页面刷新后，当前会议由 URL 恢复；若该会议已删除或不再可访问，客户端回到无选择状态并刷新会议列表。

### 7.4 删除会议

1. 只有创建者可见删除入口。
2. 客户端显示不可恢复的二次确认，并要求输入会议名称确认，降低误操作风险。
3. 服务端先原子地把会议从 `Active` 转为 `Deleting`。从该时刻起统一访问屏障拒绝新的读取、加入和写入，删除请求即被视为已接受。
4. 客户端立即从工作台移除会议并回到无选择工作台；用户自行从剩余会议中选择下一场，不自动跳转到其他会议。
5. 后台删除协调器清理本主题已有的参与者数据和会议记录；会议码从屏障建立时已经失效，不等待物理删除完成。

如果物理清理失败，会议保持 `Deleting` 且继续不可访问。启动恢复器和后续删除重试继续完成清理，不能把会议恢复为 Active，也不能在屏障已经建立后向用户报告会议仍然可用。删除请求对外只有两种幂等结果：首次成功建立屏障时返回 `202 Accepted`；屏障已经存在或会议已经物理删除时返回 `404 meeting_not_found`，客户端都按会议已不可访问处理。后续主题新增消息、连接或任务时，必须把对应资源纳入同一删除协调器。

## 8. 会议码安全

- 创建时使用 `Guid.NewGuid()` 生成会议码。随机 GUID 具有足够的首版不可预测性和唯一性，会议码方案保持简单直接。
- 数据库以 Guid 类型直接保存会议码并建立唯一索引；接口统一以标准 `D` 格式字符串展示，例如 `8f14e45f-ea5e-4f5a-a7e9-2c9d5a02b761`。
- 输入只去除首尾空白，然后按 GUID 大小写不敏感解析；解析成功后统一格式化为小写 `D` 格式。内部空白、缺失连字符或其他非标准格式不自动修复。
- 会议码是要被分享的邀请凭证，明文存储属于用户明确接受的首版取舍；普通成员详情仍不返回会议码。
- 会议码禁止出现在 URL、查询字符串、路由参数、日志、指标维度、异常正文和请求完成日志中。加入接口只接受 JSON 请求体；详情接口不返回会议码，创建者需要时显式请求邀请信息。
- 加入预检和提交在 Web 入口共享来源地址与当前账号双维度的固定窗口限流，默认每账号每 5 分钟 30 次、每来源地址每 5 分钟 100 次，允许部署配置覆盖并在启动时校验；超限返回 `429 meeting_join_rate_limited` 和 `Retry-After`，限流发生在会议码查找之前。
- 会议码缺失或超过 64 个字符返回字段验证错误；通过基础请求校验后，无法解析为标准 GUID、已删除会议和不存在会议统一返回 `404 meeting_not_found`，不提供可枚举差异。

生产环境必须使用 HTTPS；主题二的同源 Cookie、Origin 校验和业务写端点标记继续适用于创建、加入和删除。

## 9. 并发和一致性

- 会议与创建者参与者在一次工作单元中创建，不能出现无创建者会议。
- 数据库对 `MeetingCode` 建立唯一索引。随机 GUID 碰撞视为不可恢复的本次创建失败，当前作用域终止且不自动重用 DbContext；用户重新提交时生成新的会议码。
- 数据库对 `MeetingId + UserId` 建立唯一索引，保证重复人类加入幂等。
- 数据库对 `MeetingId + NormalizedDisplayName` 建立唯一索引，保证并发加入时名称统一唯一。
- 应用层预检查用于给出清晰错误，数据库唯一约束是最终一致性防线。
- 加入和删除并发时，删除状态转换与参与者写入必须通过事务条件或并发令牌保证：一旦删除屏障成功建立，新的参与者提交不得成功。

## 11. 前置与后续主题依赖

本主题依赖主题二提供的 `UserId`、当前用户昵称、Cookie 认证、当前用户上下文、`AuthenticatedLayout` 和受保护路由。会议业务不能自行解析 Cookie 或复制账号资料为新的平台身份。概念文档使用 `CreatedAt`、`JoinedAt`，服务端实体使用 `CreatedAtUtc`、`JoinedAtUtc`，HTTP DTO 使用 camelCase `createdAt`、`joinedAt`；三者都表示 UTC `DateTimeOffset`。

主题四依赖本主题输出的稳定 `MeetingId`、`ParticipantId`、成员授权、参与者名称唯一约束、工作台消息区插槽和删除访问屏障。主题五及后续 AI 主题扩展同一参与者名称空间与删除闭环，不能另建平行会议或参与者身份。

## 12. 完成门槛

本主题只有在以下结果全部成立时才算完成：

- 用户创建会议后立即进入工作台，创建者参与者和会议同时持久化。
- 会议码使用随机 Guid、明文 Guid 唯一索引、日志脱敏和加入限流；普通成员不可见，删除后失效。
- 未认证加入请求先得到 `401` 且不消耗配额，认证后限流再进入会议码查找；限流重启清零的单实例取舍已验证。
- `ParticipantDto.type` 的线上 JSON/OpenAPI 值固定为字符串 `human | agent`，不出现整数枚举。
- 创建、加入和删除的显式事务共享同一 Scoped DbContext/连接，禁止嵌套，取消和失败回滚行为通过测试。
- 创建回执能在断网重试和会议删除后阻止重复创建，Deleted 回执按 30 天策略收敛。
- 另一个账号可以直接预检并加入，且可以修改默认显示名称。
- 名称空值、规范化冲突和并发冲突得到稳定错误，不产生重复参与者。
- 用户可以创建或加入多个会议，并从同一工作台切换。
- 刷新、深链接和更换设备后可以根据账号恢复已有会议。
- 非成员不能读取会议详情或参与者列表，普通成员不能读取会议码。
- 创建者删除会议后，所有相关用户列表中都不再出现该会议，旧会议码不能再次加入。
- 删除进入 `Deleting` 后所有会议访问先被屏障拒绝，清理失败也不会重新开放。
- 工作台没有提前实现消息、实时状态或 AI 协作，也没有使用模拟数据假装这些能力已经完成。

实现步骤和测试矩阵分别在本主题设计审阅通过后编写到 `impl.md` 和 `testPlan.md`；子文档不能借实现细节扩展本主题范围。
