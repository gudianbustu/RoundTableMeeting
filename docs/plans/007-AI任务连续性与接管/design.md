# Agent 通信连续性与接管设计

## 1. 范围与依据

依据[基础需求5.12](../../需求分析/圆桌会议网站需求.md#512-连接状态与异常恢复)及增量 FR-009、FR-013、FR-015、FR-017，负责官方 CLI 后台与服务端的可靠连接。目录保留原名；产品不存在回复任务生命周期、模型阅读确认或失败队首。消息契约使用[005服务端设计](../005-实时群聊/Server/design.md)，参与范围使用[004服务端设计](../004-会议工作台/Server/design.md)。

本文为目标协议设计；内部传输由006适配，不作为外部宿主的公开MCP契约。

## 2. 身份、状态与存储

稳定 ParticipantId 属于会议；每个参与者最多一个有效 ConnectionId。连接持有递增 Generation、随机恢复凭据及状态 connected/offline/disconnected/superseded。恢复凭据只存 CLI 私有配置，服务端保存不可逆验证值，日志不输出。

连接表映射会议与参与者、代次、状态、最后心跳窗口及连续未响应次数；当前有效连接引用由参与者连接状态记录持有。收到心跳仅用于连接判断，不向页面返回最后活跃时间。操作回执按 participantId + operationId 唯一，保存入会/恢复/接管的输入摘要及结果，处理响应丢失。恢复凭据由后台在发起操作前生成并私有落盘，服务端仅保存验证值；响应丢失后后台仍持有原凭据。历史访问凭据独立于活动连接状态，但绑定当前参与者代次：断开/退出不撤销历史资格，只收紧范围；删除撤销全部内容访问资格；接管增加代次并撤销旧代次全部活跃及远端历史凭据，新会话取得当前代次资格。接管后的新Agent可读取并继续原身份有权私聊，仍受双方退出暂停及会议删除约束。旧代次不能继续取得新消息，已有外部输出不保证收回；会议删除时CLI按006清理受管副本。同步位置按会话保存，不能当作阅读位置。

同步高水位由005本人可见投影序号定义；不同参与者位置不能比较，第三方私聊不推进该身份高水位。接收确认只推进已连续落盘的范围，不能确认未收到的缺口。内部投递记录不产生模型任务，不等待发言才放行下一批。

## 3. 内部操作契约

所有操作返回 protocolVersion、operationId、连接/代次和结构化错误；输入中的身份只由已验证连接绑定解析。以下是逻辑操作，最终传输映射归006。

| 操作 | 输入 | 成功结果与约束 |
| --- | --- | --- |
| join | meetingCode、displayName、operationId、lifecycleProof | 004明确加入；返回参与者、连接及历史快照高水位 |
| reconnect | 恢复凭据、operationId、已落盘同步位置 | 恢复同一参与者；不改变已退出关系，不能恢复已删除会议 |
| takeover | meetingCode、displayName、operationId、lifecycleProof、explicit=true | 明确接管既有Agent身份，原子增加代次并使旧连接失效；继承有权私聊，不绕过退出/删除权限 |
| heartbeat | connectionId、generation、challengeId | 当前代次回应并结算相应窗口 |
| probe | 目标participantId、requestId | 同会议已加入参与者可请求；服务端向目标后台发送随机挑战并等结果 |
| receive | afterSequence、throughSequence、limit | 按本人投影序号提供全部有权类型消息；服务端从权限计算实际范围 |
| acknowledge | contiguousSequence | 已持久化连续范围；重复与较小确认幂等 |
| disconnect | connectionId、generation、operationId | 当前连接离线；不退出成员关系，不删除消息 |
| status | 当前会话或授权目标 | 在线/离线、连接错误、恢复状态；不返回阅读或模型工作状态 |

普通join/reconnect遇到有效占用，先probe。确认在线返回 connection_in_use，不隐式接管；无响应使旧连接失效后才允许原身份建立新连接。显式takeover允许在线替换；不能依赖同名猜测其他人类身份。

同一后台会话已健康连接目标会议时join/reconnect直接返回当前连接信息。operationId幂等重试不能创建新代次；相同ID不同输入返回 operation_mismatch。

## 4. 时间与恢复算法

服务端日常心跳每10秒发起一轮挑战，通过接收通道的控制信封即时送达CLI后台，后台独立于原文落盘/索引/模型读取及时响应。单轮响应窗口设计为5秒；每轮唯一challengeId，连续3轮未按窗口回应判离线。及时成功归零，迟到回应不补改已经结算的窗口。单调时钟判本进程时长，持久时间只供重启核验。主动探测最多5秒，成功确认当前连接，超时可提前使其失效；探测合并同一目标并发请求，调用方每目标每5秒最多一次，超额返回retryAfter，不累计离线次数。

后台仍运行时，暂时网络错误采用1、2、4、8、16、30秒上限退避并加0—20%抖动，成功后归零；持续网络不可达保持离线并以封顶间隔尝试。鉴权/配置错误、superseded、已退出、会议删除中或已删除为终止性错误，停止自动重连。主动断开立即取消心跳、监听及重试。

后台或电脑重启后只载入会话资料，不自动参会。Agent显式reconnect后恢复。服务端重启令内存连接不可用，旧代次必须重新验证后恢复，不能只因持久行存在就显示在线。

## 5. 接收及发送可靠性

join在同一授权快照取得基线S；实时同步范围从S之后开始，历史回补独立覆盖0至S。后台先将实时完整原文与接收位置在本地事务中提交，再ACK；ACK只证明从S起已连续收到的实时范围，不声称更早历史已回补。历史回补范围及完成度单独展示，优先处理实时接收并在间隙分页回补，不因大历史阻塞新消息。恢复沿用已经保存的基线与连续位置，不能重新取更大S跳过断线期间消息。崩溃发生在落盘后ACK前时重投按messageId去重；落盘前不ACK。同步位置、前台读取位置、提及过滤位置分别保存，历史查询不推进这些位置。

发送前生成并落盘clientSubmissionId与完整发送载荷，包含visibility、recipient和replyTo；重试不得切换公开/私聊范围。发送超时为pending_confirmation；恢复后调用005发送结果查询，已存在则补确认；确定不存在且仍可发送时使用原ID与原载荷重发；查询失败保持待确认。原正文相同但不同ID的两次正常发言不能合并。退出后允许查询本人已有发送结果但不重发；删除中/已删除不返回原消息，停止核对重发，可信删除完成后由006清除本地载荷。

主动断开后不因待确认发送而启动连接；显式重连再核对。外部模型回复使用同一消息发送链，可附replyToMessageId，不能要求taskId或任务句柄。

## 6. 并发隔离

连接替换、探测超时与旧响应使用participantId + generation条件更新。旧代次心跳、ACK、发送和断开不得覆盖新代次；返回 connection_superseded 并停止本地自动恢复。发送持久化与删除/退出共用004短事务判定，网络等待不得持有数据库事务。

同一operationId并发只返回同一结果。对过期恢复凭据返回 recovery_rejected；旧代次重放发送及结果查询均拒绝，当前代次方可核对自己的历史发送；禁止凭旧代次读取接管后私聊。退出后停止接收且固定历史上界，普通reconnect不能重新加入。删除通知失败以004专用生命周期查询收敛，服务端每次请求仍验证状态。

### 6.1 删除控制与专用确认

join/takeover登记CLI生成的lifecycleProof验证值。删除状态查询使用004专用路径，不依赖仍有效的成员/连接记录；旧代次仅可凭自身proof确认删除，不能以此恢复业务访问。删除屏障取消长轮询并返回控制状态；最终meetingDeleted只能在004清理完成后发出。通知丢失或长时间离线后，客户端优先查询删除状态，再按006处理清理；不得把连接断开、普通404或proof错误当作删除证明。

## 7. 页面与错误

页面只消费online/offline及连接诊断。CLI错误含code、阶段、是否可重试、retryAfter、修正说明；不输出凭据。网络暂时失败、connection_in_use、connection_superseded、recovery_rejected、membership_left、meeting_deleting、meeting_deleted和参数错误分别处理，不用无限重新join掩盖失败。

## 8. 兼容和交接

旧AgentReplyTask、阅读ACK、回复尝试与协作链不再驱动业务。后续迁移必须停用旧消费者，保留存续会议消息及附件事实，并按005参与者投影建立可重复同步边界；旧表是否暂存由迁移实测决定，不能删除消息来适配新模型。已被旧删除流程物理清理的数据无法凭新设计恢复；旧Deleting记录需在升级前核实已提交删除意图，并按004恢复删除，不能恢复为历史归档。
