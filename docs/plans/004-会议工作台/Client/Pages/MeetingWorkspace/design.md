# 会议工作台页面设计

## 1. 页面定位

`MeetingWorkspacePage` 是登录后的默认业务页面，承载用户的会议导航和当前会议静态工作区。它替换主题二的登录后身份占位页，但继续位于 `AuthGate -> AuthenticatedLayout` 内。

## 2. 进入条件

- 当前用户已经通过主题二认证；
- 路径为 `/` 或 `/meetings/:meetingId`；
- 会议权限由服务端详情接口判断，页面不根据列表存在性自行授权。

## 3. 页面结构

页面由以下区域组成：

1. 会议导航区域。
2. 当前会议主区域。
3. 主区域顶部 `MeetingHeader`。
4. 静态 `ParticipantList`。
5. 主题四消息区域插槽。
6. 创建、加入和删除确认对话框；页面拥有对话框状态，`MeetingHeader` 只触发删除回调。

页面不在单独卡片中包裹整块工作台，也不重复认证后布局的品牌和用户栏。

## 4. 无会议状态

会议列表成功且为空时，主区域显示简洁空状态和两个明确入口：创建会议、使用会议码加入。页面不展示使用说明长文、不预置样例会议或假参与者。

会议列表非空但未选择会议时，提示从导航选择会议，并保留创建/加入入口。

## 5. 有会议状态

当前详情成功后：

- 会议头部展示名称、背景、创建时间和当前显示名称；创建者额外看到会议码邀请信息；
- 参与者区域展示全部静态参与者；
- 消息区域显示后续主题接入的空状态；
- 创建者可见删除入口，普通参与者不可见。

会议码只对创建者显示，复制操作必须直接可用，并且不会把会议码写入 URL、本地存储、详情缓存或 DOM 以外的持久化位置。加入对话框中的会议码只保留在组件内存状态，关闭或完成加入后清除。

## 6. 加载与失败

- 列表首次加载失败：主区域显示服务不可访问和重试，导航不伪装为空。
- 详情加载：只对主区域显示局部加载，会议导航仍可操作。
- 详情 404：清除当前详情并导航 `/`，在工作台主区域顶部显示会议不可访问提示并刷新列表；提示不自动消失，用户选择会议或关闭提示后清除，列表非空也不自动导航。
- 详情网络失败：保留旧详情但标记数据可能过期，提供重试。
- 邀请信息加载失败：只在创建者邀请区域显示重试，不影响会议详情和参与者列表。
- 删除命令被接受后：立即禁用详情操作并导航离开。

## 7. 响应式行为

桌面端导航和主区域并列；窄屏导航折叠在主区域上方。页面设置稳定的网格列宽和最小高度，列表加载、长会议名称、按钮 loading 或参与者数量变化不能导致不可控横向滚动。

长会议名称和参与者名称允许换行，会议码使用等宽字体并可完整选择复制；不依赖缩小字体适应。

## 8. 页面边界

页面只组合组件和模块 Hook，不直接调用生成 Client、不解析 ProblemDetails、不保存会议码、不实现成员授权。
