# 群聊与附件服务端实现计划

## 1. 数据与文件边界

按[Server设计](design.md)，先核对现有消息实体、事件目录、幂等索引和事务Runner。隔离旧库副本保留消息ID/顺序/作者/原文；新增Attachment和可选回复引用，修订原文写入规则，停用旧任务派生；增加visibility、recipient与本人可见投影，接入004整会删除。

配置附件数据目录与MaxFileBytes=100000000，启动校验实际可写性及正数上限；定义临时文件/已完成文件原子移动和暂存补偿。上传/绑定/超时暂存清理必须能在磁盘满、崩溃、并发情况下收敛，存续会议不自动清理已绑定附件，整会删除时全部清理。

## 2. 应用与入口

执行[模块计划](Modules/RealtimeChat/impl.md)。Human、System和受信Agent共享核心；附件下载、列表、历史、发送核对共用004权限。新增大小错误、提交冲突和生命周期错误映射，Origin、no-store、日志脱敏保持一致。

更新真实OpenAPI后再生成Kiota。HTTP与Agent协议同形状但认证适配分离，不允许外部伪造participantId。Range/Content-Disposition/nosniff及预览类型作为真实HTTP集成测试。

## 3. 实时与在线

SignalR维持独立适配和每连接授权；新增会议/成员状态事件，退出停止本人订阅但保留有权历史；删除阻断全部读取并清理数据。保留按消息ID去重和缺口补读所需高水位。事件Dispatcher每次独立scope，失败不撤销已存消息；Agent只读取全部有权消息，私聊事件仅发双方，无回复任务消费者。

## 4. 验证

执行真实SQLite事务与约束、文件故障、HTTP/SignalR、旧库迁移和C01—C10关联测试。浏览器锚点归客户端，官方CLI恢复归006/007；构建不替代联调。当前已实现参与者投影、范围/回复、完整载荷幂等、本人结果查询、定向SignalR和附件闭环；已在隔离库及文件目录验证原生升级/降级保护、第三人权限、退出上界、上传/绑定/Range/删除和暂存恢复。最终汇总集成回归排除已停用的McpAgentContractTests/AgentMentionTaskConsumerTests后，161项全部通过，包含5项历史消费者兼容用例、协议切换与文本预览专项。完整旧MCP套件未作为当前协议执行；详细通过项与剩余故障场景见主题测试计划。共享运行库未修改，未发布；测试实例按需启动/重启。官方CLI适配仍归第3批。
