# 实时群聊与附件主题设计

## 1. 依据与范围

依据[基础需求](../../需求分析/圆桌会议网站需求.md)及FR-001、FR-003、FR-008、FR-011、FR-013、FR-017，建立人类、Agent和System共用的持久消息流、附件、历史分页及Web阅读交互。沿用004工作台与授权，Agent入口在006/007扩展同一追加核心。

@只确定关注对象；无回复任务、已读未读、阅读ACK、遗漏@提醒、工作状态或业务完成判断。平台保留原文，不提供撤回、单条删除或清空。

## 2. 设计决定

消息保存、提及、附件绑定和持久化通知事件在同一事务；服务端顺序为事实，实时通知可重复或丢失，客户端按标识去重并补读。发送超时显示待确认，只有服务端确认落库后显示已保存。

完整历史采用位置分页；MCP 工具输出容量不限制服务器保存。退出后按004历史权限继续读原文和附件；整会删除后所有人不可再读。网页上滑时固定阅读锚点，在底部时跟随，通过主动入口回到最新。按 FR-018 显示当前设备的各会话未读数与会议合计，浏览某一会话仅推进该会话的已读位置。

附件由人类和Agent共同使用，不限制扩展名，单文件默认100 MB且部署可配置。网页安全预览或下载，Agent 按会议授权下载，附件清单可定位原消息；不增加OCR、解析、版本、文件夹或必读状态。

## 3. 唯一契约与分工

[Server/design](Server/design.md)维护消息、提及偏移、分页、附件传输/存储、错误与实时协议；[Server模块](Server/Modules/RealtimeChat/design.md)维护应用调用与事务编排。[Client/design](Client/design.md)维护阅读锚点、连接恢复及状态；模块、页面、时间线与编辑器子文档展开实现责任。

共享模型见[领域图](../../uml/圆桌会议协作模型.puml)。会议与成员归004，消息/附件归005，连接归007，原生 MCP 与官方脚本接入归 006；不将数据库表数量解释为新的业务主题。
