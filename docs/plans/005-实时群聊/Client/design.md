# 实时群聊客户端设计

## 1. 工程与契约

沿用features/meetingWorkspace的API适配、chat reducer、RealtimeChatRegion、MessageTimeline和MessageComposer。只有meetingChatConnection适配文件依赖SignalR；页面/组件不直接操作生成Client。[服务端设计](../Server/design.md)是HTTP、消息和附件契约唯一来源。

## 2. 状态与恢复

每个meetingId+交流范围(public或私聊双方ID)维护messagesById、按sequence排序的ID、历史边界、highWatermark、connection generation、授权上界、草稿、待确认发送和滚动锚点。按messageId去重，序号决定显示顺序，冲突内容不覆盖原服务端事实。

活跃会议进入时先建立连接缓冲事件，订阅取得高水位，读取最新页，再afterSequence补齐缺口并合并事件。历史模式直接HTTP分页，不建立活跃订阅。before加载不当成实时缺口；重连仅补尚缺序号。切会/注销先增加generation，再取消请求和解绑连接；旧请求不能更新新会议。

membershipLeft重载权限，保留已有有权消息且暂停相关双方私聊。meetingDeleting/meetingDeleted移出会议并清理全部公开/私聊缓存、草稿和附件ObjectURL，取消请求并递增generation；删除后无历史模式。网络失败与普通404不作为本地删除完成证明。

## 3. 阅读位置

底部判断使用scrollHeight-clientHeight-scrollTop<=48 CSS px作为设计默认阈值；在底部时新消息提交后跟随。用户上滑后保存首个可见messageId及其到容器顶部的像素偏移，加载更早消息、附件尺寸变化、字体换行或实时追加后恢复同一锚点。ResizeObserver触发布局稳定后修正，不用定时刷新强制置底。

“回到最新”按钮在非底部时出现，不带未读数、催促或遗漏提示。点击后定位最后消息并恢复底部跟随。按meetingId与交流范围在当前页面内存保留锚点，切回时按该messageId加载附近页恢复；刷新默认最近页，不持久化消息正文到localStorage。图片预先给出尺寸占位，未知尺寸加载后按锚点补偿。

## 4. 发送状态

发送状态跟随时间线中的本地待发送消息：sending显示小转圈，pending_confirmation显示中性“待确认”及核对入口，明确rejected显示红色感叹号，点击后查看真实失败原因并重试；saved只保留服务端消息，不额外提示。编辑器不显示成功/失败文案或重试按钮。本地待发送项显示原正文和附件名称，以clientSubmissionId标识，不伪造服务端messageId或sequence；成功后移除占位。编辑已明确失败的草稿时撤销原失败占位，作为新的发送意图。退出后的待确认项仅允许核对，不允许重发。发送前生成一次clientSubmissionId，正文/附件/引用/visibility/recipient作为不可变待确认载荷；编辑后发新意图才生成新ID。超时先查询提交结果，saved合并原消息，确定not_found且可发送才重发；查询失败保持待确认。

HTTP响应与广播竞态按messageId合并。发送中本地占位无伪造sequence；失败保留草稿和附件暂存引用。退出后只查询结果；删除中或已删除停止内容查询与重发，并清理待发载荷。仅显示自己的提交状态，不展示接收者已读。

## 5. 编辑器与提及

输入使用参与者目录辅助插入@显示名称，记录原文UTF-16范围，不修改正文规范化。服务端mentions是最终高亮事实，按文本节点渲染。未知@或无@正常发送，无遗漏提醒或额外确认。引用只选有权消息，不能推断必须回复。

附件入口展示本地添加错误及实际大小限制，上传进度和失败重试由时间线待发送消息展示；点击发送后先上传、全部成功再提交消息绑定。无正文但有附件允许发送。不可预览文件提供下载。会议附件抽屉按“文件”“图片”两个Tab区分，默认文件；图片页收纳PNG/JPEG/GIF/WebP，其他附件保留文件卡片。两页保留发送者、时间、完整预览/下载和跳转原消息，共享当前交流范围的已加载分页数据；切换Tab不重发请求，未加载完时不能把当前类别为空表述为全部不存在，继续提供加载更早附件入口；跳转需按ID加载附近页并定位，不依赖该消息已在当前缓存。

## 6. 展示、安全与状态

纯文本与提及通过React文本渲染，不注入HTML；附件预览遵循服务端安全类型：光栅图片使用图片元素，PDF按需加载PDF.js在本地Worker解析并绘制到Canvas，使用已移除动态代码求值的PDF.js 6，不执行文档脚本或创建交互表单/链接。PDF支持逐页切换、失败重试，关闭时取消渲染并释放文档；文件名不可作为HTML。长文本自然换行，保留原文空白。新消息不更改浏览器标题计数。

参与者online/offline交004组件，连接诊断显示在消息区状态栏；不显示最后活跃、模型思考或阅读状态。网络失败、历史加载失败和提交失败分别提供重试，单个附件预览失败不阻塞文本阅读。按钮键盘可操作且带aria-label，移动端不因附件横向撑破布局。

图片在消息及附件清单中独立展示：PNG/JPEG/WebP保持完整比例，GIF直接播放，不裁剪、不放大小图，不常驻文件名、大小或操作栏。图片采用最大320px宽、240px高的固定透明展示区域，加载、成功和失败不改变占位；点击图片（键盘Enter/Space同样可用）打开完整预览，弹框提供下载，GIF继续播放。文字和图片混发时文字在前、图片在后，多个附件按发送顺序排列。PDF、文本及其他文件继续使用卡片：固定140px预览区展示PDF首页和页数、文本前几行或文件图标，底部显示文件名、大小及下载/预览按钮。文件卡片统一320px宽，受容器限制时缩至可用宽度；空文件与其他文件等宽，不随内容长度收缩。长文件名省略并可查看全名，多附件自适应换行。图片和缩略内容进入视口附近才加载，离开时释放内容；读取使用相同鉴权接口。纯文本最多读取前8KiB，始终按纯文字显示。

## 7. 私聊选择、回复与隔离

工作台保留公开讨论入口，参与者列表或消息作者操作可打开与该参与者的私聊区域。状态键为meetingId+scope+peerParticipantId；私聊头部持续标明“私聊”和对方名称，消息标明发送者。第三人及未参与的创建者不获得该私聊的列表项、时间、数量或提示，不从公共事件推断私聊关系。进入私聊只改变本人的视图，不向全会广播动作。

点击回复私聊固定原双方及visibility；页面切换和正文@均不能改变已保存草稿/待发送载荷范围。返回公开区使用独立公开草稿；用户明确选择“公开发送”时建立新的public意图，清除私密replyTo和原附件绑定，不自动摘录原私聊。既有私聊记录不被改为公开。接口冲突按Server错误呈现，不默默转换目标。

私聊时间线、附件清单、定位、前后文均限同一双方；公开区域不自动拼入私聊引用预览。双方任一退出即暂停发送并说明原因，但仍可读已有内容；对方离线仅显示连接离线，允许留言。明确重入后重新获取双方资格，不能由打开页面恢复参与。创建者删除会议时，两类区域一并销毁，不保留私聊独立入口。

HTTP和SignalR收到的sequence为当前参与者可见投影，不能比较其他人的位置。选定scope后序号间隔可能来自本人其他有权范围，不用缺号判断丢消息；补读以服务端scope分页hasMore和高水位为准。前端过滤仅用于展示，不能替代服务端不向第三方发送数据。

预览类型为PNG/JPEG/GIF/WebP、PDF和纯文本。纯文本按txt/md/log/csv/tsv/json/xml/yaml/yml/ini/conf扩展名识别，仅在服务器识别为通用二进制时启用；按文本转义显示，不渲染Markdown/HTML。默认按BOM或UTF-8识别，非UTF-8尝试GB18030，并允许手选UTF-8/GB18030/UTF-16LE/BE。最多预览前1 MiB并明确提示截断；空文件、解码失败和图片加载失败有明确状态与重试。HTML/SVG及Office、压缩包等没有预览入口，保留下载。

## 8. 输入区工具布局

消息区顶部不再单独放公开/私聊及附件入口。输入框上沿工具栏左侧为一个文字选择器，显示“公开讨论”或“私聊 · 对方姓名”，私聊用紫色标识，消息框、范围下拉框与输入框统一左右边界（下拉框左边与两框对齐），四周预留一致边距；私聊时消息框和下拉框也持续显示紫色边框及柔和外扩阴影，输入框显示紫色边框、淡紫底色和柔和外扩阴影，发送按钮使用紫色，禁用时使用低饱和淡紫且保持不可操作，聚焦时加强紫色边框与光晕，失焦后仍清晰可辨；输入框四周预留阴影空间，公开/私聊切换不改变输入框尺寸，返回公开讨论恢复普通样式；选项包含公开讨论和可选参与者，切换仍按会议与双方隔离草稿、附件和待确认载荷。工具栏右侧为文件夹图标，悬停显示“会议附件”，打开当前范围的文件/图片抽屉。输入框内部左下角为回形针图标，悬停显示“添加附件”及实际单文件限制；限制不常驻占一行。现有会议操作保留在其后，发送按钮保持右侧。上传状态、错误、重试和已就绪文件保留可见反馈；只读时保留范围切换与附件查看，禁用上传发送。窄窗口工具栏保持两端，底部允许换行但不溢出。

待发送附件位于输入框内部、正文输入区上方，使用自动折行容器。图片与普通文件统一采用40×40px紧凑卡片，间距和移除按钮位置一致，图片显示完整缩略图，普通文件显示图标，文件名与大小通过悬停查看，各项保留移除入口。附件区域最多显示约两行高度，更多内容在区域内滚动，避免挤掉正文输入；无附件不占位。添加入口保留在底部工具栏，上传进度和失败重试显示在时间线待发送消息旁，文件不在底部逐行展示。移除不清空正文，按公开/私聊隔离保留附件，发送期间不可移除。

待发送附件只保留在当前浏览器内存草稿中，使用File/Blob生成临时地址预览，不调用服务器上传或内容接口；刷新页面会丢失尚未发送的本地附件。移除、成功发送或卸载时释放临时地址。

输入框支持粘贴图片、拖入文件和文件选择器多选，三个入口只添加本地File并校验单文件大小与20项上限，不上传。普通文字粘贴不拦截；图片和文件卡片统一40×40px。点击发送后才按顺序上传附件，全部成功后提交包含真实附件ID的消息；本地临时ID不能发给消息接口。发送期间锁定编辑、添加和移除；失败保留原文与本地附件，重试复用原上传请求ID、已成功上传结果和消息提交ID，不重复上传成功项。上传失败不提交部分附件消息。上传阶段切换范围取消剩余上传并保留可重试草稿；消息提交阶段中断则保留待核对状态，不能盲目重发。

待发送附件点击或键盘Enter/Space打开本地Blob预览，图片、PDF和纯文本与已发送附件共用预览类型判断及组件，仅数据源不同；不请求服务器内容接口。没有本地File的旧版草稿提示重新选择，不能绕过权限读取服务器暂存内容。关闭、移除或切换范围释放预览地址；Office、压缩包、HTML/SVG等仍提示不支持。预览不发送消息，不改变草稿。

音视频预览复用AttachmentPreview：按安全媒体MIME或octet-stream文件扩展名白名单识别音频MP3/WAV/OGG/OGA/M4A/AAC/FLAC、视频MP4/M4V/WebM/OGV/MOV。卡片展示音频/视频图标及预览入口，不在消息列表加载媒体；弹窗按需挂载原生audio/video，controls、preload=metadata、视频playsInline，不autoplay。加载失败提供重试及格式/网络提示；关闭/卸载暂停、清除src并load释放，Blob由草稿组件释放。服务器内容沿用权限与Range，草稿保持本地Blob。
