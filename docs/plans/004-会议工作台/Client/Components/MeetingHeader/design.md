# 会议头部组件设计

## 1. 组件职责

`MeetingHeader` 展示当前会议基本信息；在父模块明确提供邀请信息时展示会议码复制操作，并展示创建者删除入口。组件不加载详情、不判断当前用户，只消费 `MeetingDetails`、可选 `MeetingInvitation` 和回调。

## 2. 展示

显示会议名称、可选背景、创建时间、当前用户会议内显示名称。头部全部操作使用图标按钮（图标 + `aria-label`/`title`），不渲染文字标签。创建成功响应自带邀请信息时立即展示；之后重新进入会议时，创建者通过“显示邀请码”图标按钮显式加载。加载成功后会议码使用固定宽度或等宽样式完整显示，并提供复制与隐藏图标按钮。隐藏操作必须通知父模块清除邀请码内存状态。普通人类成员也渲染会议码区域。

`canManageInvitation` 为 true 时，头部首位渲染“邀请入会”主色图标按钮，作为邀请流程（见 `InviteMeetingDialog`）的唯一切入点。刷新按钮触发父模块重新读取当前详情，loading 期间保持稳定尺寸并禁止重复请求。只有 `canDelete` 为 true 时显示危险删除图标按钮。首版不提供编辑名称、修改背景、重新生成会议码、结束会议或退出会议。

## 3. 复制

点击复制调用 Clipboard API。成功显示短暂成功反馈；失败显示“请手动选择并复制”的可理解提示。会议码不写入日志、URL、localStorage 或详情缓存。

## 4. 删除

删除按钮只调用 `onDeleteRequested()`，由工作台页面挂载二次确认对话框。对话框要求输入完整会议名称，Trim + NFC 后使用大小写敏感的精确匹配；输入值随删除命令提交到服务端，不能只在客户端判断。提交期间禁用所有头部操作；父模块负责调用删除 API 和导航。
