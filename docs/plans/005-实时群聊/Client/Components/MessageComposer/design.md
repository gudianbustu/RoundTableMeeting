# 消息编辑器组件设计

## 1. 组件职责

`MessageComposer` 管理当前草稿、键盘输入、参与者提及候选和发送/失败显示。发送时向模块提交正文和候选范围，不提交作者身份或服务端字段。

## 2. 输入规则

- 多行文本框允许换行；若启用 Enter 发送、Shift+Enter 换行，仍必须提供可见发送按钮和无障碍名称。
- 只做空白提示和长度预检，服务端错误仍为最终结果。
- 候选列表来自当前会议参与者，区分 Human/Agent 类型；未知 `@` 文本仍可发送。候选范围在提交时针对 NFC+Trim 后的实际请求正文重新计算，不沿用已经因编辑失效的旧偏移。

## 3. 发送状态

- idle：允许编辑和发送；
- sending：锁定当前提交按钮但保留草稿内容；
- failed：保留原文和同一 clientSubmissionId，提供重试；
- 成功：由父模块清除草稿。

组件不直接调用 API、不生成服务端序号、不在本地时间线插入乐观消息。
