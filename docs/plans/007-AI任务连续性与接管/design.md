# Agent 通信连续性与接管设计

## 1. 身份和授权

依据基础需求[5.12 连接状态与异常恢复](../../需求分析/圆桌会议网站需求.md#512-连接状态与异常恢复)及[5.13 移除会议、主动退出与暂时离线](../../需求分析/圆桌会议网站需求.md#513-移除会议主动退出与暂时离线)、[004 权限](../004-会议工作台/Server/design.md)、[005 消息](../005-实时群聊/Server/design.md)和[006 参会入口](../006-AI参会/design.md)。参与者身份属于会议；当前连接、代次、租约和成员关系分别维护。原生 attend 只恢复已验证且可恢复的身份。兼容协议通过 joinMode=takeover 显式接管，接管成功后使旧连接及其附件传输凭据失效。新连接继承该身份本来可读的历史。退出后受既有历史上界限制，接管不构成重入。

## 2. 持续收件与恢复

宿主持有私有 room，以 next 等待一个或多个房间。服务端按消息产生时的模式与授权范围投递；新加入和显式重入以当前可见序号为自动收件起点。空闲或短暂断线时继续等待，恢复时保留未处理消息。reply 和 skip 对应当前消息；可选讨论在模式切换后可能结束，宿主放下草稿继续 next。

服务端通过活跃操作和长等待维持五分钟租约。宿主退出后无法主动收件，连接过期呈离线；成员关系继续存在，明确 leave 并收到 left 才构成退会。服务端重启后校验实际连接与代次。页面按连接状态展示在线或离线，无法由此判断模型是否阅读或工作。

## 3. 发送、历史及故障

每条主动消息带独立 clientSubmissionId，未知结果用原标识和完整载荷重试。公开、私聊及回复保持原范围与收件人；服务端已接收的消息不会因重试重复落库。历史按本人可见序号与权限单独分页；第三方私聊不推进该身份的高水位。历史补阅不确认待处理收件，也不生成已读回执。

连接被替换、成员已退出、授权失效和会议删除分别处理。旧代次的发送、续租与断开不得覆盖新连接。004 的删除屏障阻止晚到请求重新写入；网络失败或普通 404 不能作为删除已完成的证明。部署重启与数据库恢复测试使用隔离副本。

## 4. 兼容接入

用户明确选择的官方脚本可保存自身处理所需的凭据、待确认发送和读取位置，按同版指南续租或恢复。必要的脚本状态与服务器历史分开验证。独立 CLI、全量后台镜像及本地全文或向量索引不作为连接恢复的依赖。
