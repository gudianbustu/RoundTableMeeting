# 认证后布局组件设计

## 1. 组件职责

`AuthenticatedLayout` 是认证成功后的应用级布局，负责提供受保护页面共享的结构、当前用户栏和子路由渲染位置。它不判断凭证、不解析 Cookie、不查询会议数据，也不提供用户管理功能。

## 2. 结构

布局包含：

1. 应用标题或品牌区域。
2. `CurrentUserBar`，显示当前用户并触发退出。
3. 主内容区域，通过 Router Outlet 渲染受保护页面。
4. 主题三后续接入会议工作台的稳定内容插槽。

布局不在登录页或公开系统状态页中使用。

## 3. 认证边界

- 路由配置在布局外层使用 `AuthGate`，布局本身假定已处于 `authenticated` 状态。
- 如果认证状态在使用过程中变为匿名，Provider 和路由边界负责导航到 `/login`。
- 布局不通过客户端是否存在用户对象来决定权限。
- 当前用户资料来自认证 Context，不从 URL、localStorage 或页面参数读取。

## 4. 退出行为

用户在 `CurrentUserBar` 点击退出后：

1. 认证模块调用退出 API。
2. 当前用户状态被清理。
3. 路由返回登录页。
4. 原受保护页面不能继续作为已认证内容显示。

布局只负责提供退出操作的承载位置，不重复实现退出流程。

## 5. 后续扩展

主题三可以在主内容区域接入会议列表和工作台，但必须继续保留认证 Provider、`AuthGate` 和 `CurrentUserBar` 的职责边界。会议成员权限和会议数据加载由会议 feature 自己负责。
