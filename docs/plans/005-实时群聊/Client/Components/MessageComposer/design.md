# 消息编辑器设计

提供原文输入、参与者@辅助、附件上传和发送；纯附件可发，空正文且无附件拒绝。未知@或无@正常发送，不增提醒。仅权限允许活跃收发时可操作。

附件入口展示本地添加错误和实际限制，上传进度、发送状态和失败操作由时间线对应消息展示；保留原载荷和草稿，重试由模块协调。不能用模型回复或接收ACK判断发送完成。

详细状态、48px底部阈值、锚点和安全边界统一见[客户端设计](../../design.md)，不重复定义协议。

编辑器接收显式scope和peerParticipantId，持续显示公开或私聊对象。回复继承原私聊范围；切页与@不改目标。公开发送必须显式选择，具体载荷转换按Client设计第7节；不能自动公开引用或复用私密附件绑定。双方参与资格不足时禁用发送但保留可读历史。

输入区布局遵循Client设计第8节：附件上传入口位于编辑器底部工具区首位，图标保留可访问名称及大小限制提示；范围选择与附件清单位于编辑器上沿。

待发送附件位于输入框内部、正文输入区上方，使用自动折行容器。图片与普通文件统一采用40×40px紧凑卡片，间距和移除按钮位置一致，图片显示完整缩略图，普通文件显示图标，文件名与大小通过悬停查看，各项保留移除入口。附件区域最多显示约两行高度，更多内容在区域内滚动，避免挤掉正文输入；无附件不占位。添加入口保留在底部工具栏，上传进度和失败重试显示在时间线待发送消息旁，文件不在底部逐行展示。移除不清空正文，按公开/私聊隔离保留附件，发送期间不可移除。

待发送附件只保留在当前浏览器内存草稿中，使用File/Blob生成临时地址预览，不调用服务器上传或内容接口；刷新页面会丢失尚未发送的本地附件。移除、成功发送或卸载时释放临时地址。

输入框支持粘贴图片、拖入文件和文件选择器多选，三个入口只添加本地File并校验单文件大小与20项上限，不上传。普通文字粘贴不拦截；图片和文件卡片统一40×40px。点击发送后才按顺序上传附件，全部成功后提交包含真实附件ID的消息；本地临时ID不能发给消息接口。发送期间锁定编辑、添加和移除；失败保留原文与本地附件，重试复用原上传请求ID、已成功上传结果和消息提交ID，不重复上传成功项。上传失败不提交部分附件消息。上传阶段切换范围取消剩余上传并保留可重试草稿；消息提交阶段中断则保留待核对状态，不能盲目重发。

待发送附件点击或键盘Enter/Space打开本地Blob预览，图片、PDF和纯文本与已发送附件共用预览类型判断及组件，仅数据源不同；不请求服务器内容接口。没有本地File的旧版草稿提示重新选择，不能绕过权限读取服务器暂存内容。关闭、移除或切换范围释放预览地址；Office、压缩包、HTML/SVG等仍提示不支持。预览不发送消息，不改变草稿。
