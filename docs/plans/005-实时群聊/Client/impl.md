# 群聊客户端实现计划

1. 按[客户端设计](design.md)扩展既有listMessages/sendMessage/meetingChatConnection适配，接入真实Kiota，增加发送结果、附件上传/清单/下载和消息定位。
2. 按[模块计划](Modules/RealtimeChat/impl.md)维护按ID去重、序号补齐、generation、权限上界及待确认发送，不把超时直接标失败。
3. 更新[区域页面](Pages/RealtimeChat/impl.md)、[时间线](Components/MessageTimeline/impl.md)与[编辑器](Components/MessageComposer/impl.md)，接入阅读锚点、回到最新、附件和纯文本提及。
4. 退出保留有权历史及附件，暂停双方私聊；删除移出入口并清理公开/私聊缓存与草稿；普通网络恢复不join。
5. 执行根C02/C03/C07/C08/C10组件和真实浏览器验收，重点检查新消息、旧页插入、图片尺寸变化及切会；当前已实现并通过组件回归和三浏览器人类会话验证；当前声明支持的图片/PDF/文本类型已逐类浏览器验证；完整锚点压力及跨浏览器/物理设备兼容继续归第4批。

6. 按Client第7节接入私聊选择、范围隔离的草稿/滚动、默认回复与显式公开发送，执行C11—C14；服务端及网络事件不得向第三方提供私聊发生信息。

7. 图片消息与附件卡片：图片独立完整显示、GIF直接播放，点击展开完整预览并下载；PDF/文本/其他文件保留卡片。保持按需加载、固定占位、鉴权和公开/私聊复用。已实现并验证：消息内GIF播放、完整比例显示、公开/私聊及附件清单预览下载入口、窄窗口、失败后重试与阅读位置稳定。浏览器临时尺寸样本验证小图不放大及长图不裁剪；前端178项回归、类型检查和生产构建通过。

8. 附件抽屉分类：按文件/图片Tab展示，保留公开/私聊范围、共享分页、空态提示及原消息定位；已完成。组件回归覆盖分类、切换不重复请求、共享游标继续加载、最终空态和原消息定位；浏览器公开22文件/7图片、私聊3文件/4图片分类与预览、定位通过。

9. 发送反馈移至消息旁：已实现本地待发送项、发送中转圈、失败感叹号/原因/重试、结果待确认核对；去除编辑器成功提示，复用现有不可变载荷和幂等确认流程。前端178项全量回归、类型检查及生产构建通过；实际浏览器故障注入验证明确失败、同ID重试、发送中占位、成功单条合并、未知状态先核对及公开/私聊隔离。

10. 本人消息靠右：按当前参与者ID识别，公开/私聊的元信息、正文、图片、文件及本地待发送项统一靠右；已完成；浏览器验证公开/私聊本人靠右、他人靠左，图片及文件按原顺序单列右对齐，混合附件不保留空列；503px窄窗口长文本、发送中与失败状态无横向溢出，待发送/已保存方向一致。178项前端回归、类型检查及构建通过。

11. 输入区工具整合：先更新布局设计，再将附件上传移至内部左下角，范围选择器/附件清单移至上沿两端；已完成。178项前端回归、类型检查及构建通过；实际浏览器验证回形针上传/大小提示、公开与私聊草稿附件恢复、私聊紫色标识、对应附件Tab和窄窗口横向布局，底部回形针与会议操作同排。

12. 私聊区域强调与对齐：消息框、下拉框和输入框左边对齐，消息框与输入框右边对齐；三者持续显示紫色边框和外扩阴影，输入框与下拉框有淡紫底色，发送按钮可用时紫色、禁用时淡紫，聚焦时加强，切回公开恢复普通样式；预留阴影边距。类型检查、构建及浏览器聚焦/失焦、范围切换、窄窗口横向检查通过。

13. 待发送附件卡片：图片和文件统一40×40px，正文上方自动折行并限制区域高度；只在当前浏览器内存草稿中保留File，按公开/私聊范围隔离，刷新页面会丢失未发送的本地附件。预览使用本地Blob地址，关闭、移除、成功发送及卸载释放资源。

14. 附件多入口与发送：粘贴图片、拖入文件、多选文件只添加本地文件并校验大小和20项上限。点击发送后固定正文、附件、范围和回复，串行上传全部附件后才提交消息；上传进度与失败重试在时间线待发送消息旁显示。失败保留草稿，重试复用原上传请求ID及消息ID并跳过已成功项；上传中切换范围取消上传并保留重试，消息提交中切换保留待核对状态。168项前端回归、类型检查及生产构建通过，浏览器验证无提前上传、失败不提交部分消息、成功项不重复上传及连续点击防重。

15. 待发送附件点击预览：所有文件保留本地File，图片、PDF、纯文本与已发送附件复用预览组件；本地预览不调用服务端内容接口。缺少本地File的旧草稿提示重新选择，不支持类型显示说明。组件覆盖Blob生命周期、图片重试、纯文本安全呈现和只读状态；浏览器文本预览仅有Blob读取。服务端未绑定附件仍不可读取，AttachmentTests 6项通过。

16. 音视频附件预览已实现：待发送附件、消息和附件清单共用原生audio/video播放器，按需加载、不自动播放，支持控制、失败提示和重新加载；关闭时暂停并清除源，StrictMode重复挂载可恢复。媒体卡片不提前读取媒体内容。前端34文件178项全量回归通过，修复后10项播放器定向回归、类型检查及生产构建通过；真实Chrome的WebM/WAV播放、暂停、跳转和关闭释放通过。
