# 会议工作台主题设计

## 1. 依据与目标

承接[基础需求](../../需求分析/圆桌会议网站需求.md)及增量FR-005、FR-007、FR-012、FR-015，在现有工作台完成创建/加入、多会议切换、信息编辑、参与者列表、邀请及关闭/退出后的历史访问。沿用002框架与003账号；本轮只修订设计。

## 2. 范围与产品语义

会议创建即开放并长期保存。创建者可编辑名称、讨论主题或背景；已加入人类成员可取得邀请信息。只允许创建者移除会议，移除表示关闭全部交流并保留历史；非创建者可主动退出，保留退出前历史。创建者退出请求必须拒绝，不能隐式关闭。

断开连接不改变参与关系。历史入口不重新加入；明确用有效会议码重新加入开放会议才恢复完整历史，沿用原参与身份和显示名。关闭不可重新加入。参与者展示在线/离线，离线组默认折叠，不展示邀请人、所属人、最后活跃、已读或模型工作状态。

不建设预约、主持、踢出、禁言、转让创建者、消息删除或回收站。消息/附件实现归005，Agent连接归006/007；本主题提供统一权限与界面组合。

## 3. 契约与单一来源

[服务端设计](Server/design.md)唯一维护模型、规范化、状态、历史上界、API、错误及事务。所有调用方区分历史读取与活跃收发，不能用“非active一律404”阻断历史。共享模型引用[领域图](../../uml/圆桌会议协作模型.puml)。

[客户端设计](Client/design.md)负责工作台状态、当前会议、历史入口和标题同步；组件不自行决定权限。会议代码/元数据/权限变化通过revision收敛，旧请求不覆盖新会议。

## 4. 可见流程

创建后进入会议；首次加入预览名称与背景、确认本人显示名；重复加入复用身份。创建者编辑后刷新详情和导航，当前页面标题同步。移除前明确提示“关闭所有人的交流，保留历史”，操作成功转只读历史；退出提示“停止参与，仍可查看退出前记录”，只影响自己。

活跃与历史分组共享导航，关闭或退出后移至历史入口。历史仍显示有权读取的消息与附件，隐藏发送/邀请等不可用操作并说明原因。此前退出者的范围不能因关闭扩大。
