# 多 Agent 协作与会议删除收口主题设计

## 1. 定位与依据

本目录编号 008，对应总体计划中的主题七，也是首版最后一个实施主题。本文定义待实现的契约，不表示功能已经实现或验收通过。

依据：[产品需求](../../需求分析/圆桌会议网站需求.md) §5.7、§5.13，[总体计划](../001-总体计划/design.md) §7.7，[AI 参会设计](../006-AI参会/design.md)，[AI 任务连续性与接管设计](../007-AI任务连续性与接管/design.md)。连接、确认、租约、重试和恢复以主题六的扩展契约为准。

本主题在统一消息流、持久化消息事件、每个 AI 的 FIFO 任务和可靠恢复之上，增加 Agent 消息触发 Agent、协作来源追踪，并对全部资源组合完成会议删除收口。具体实施步骤见[实现计划](impl.md)，验收用例见[测试计划](testPlan.md)。

## 2. 平台职责与产品规则

网站提供人类与外部 Agent 相互交流的场地。协作是否达成一致、是否完成、是否冻结以及下一步应当通知谁，由当时参与的 Agent 和用户自行判断；平台不固化具体审查流程、角色分工、轮数或完成条件。

平台不按协作深度、累计任务数、重复参与者或正文相似度判定业务循环，不自动截断协作，不提供暂停协作、恢复协作或停止外部 Agent 的网页/MCP 入口。需要停止执行时，由人类直接操作对应 Agent 的外部工具；平台不依赖 Agent 正在工作时能及时接收一条停止消息。

以下技术规则仍然成立：

1. Human 和 Agent 消息中的有效 @AI 都可以产生任务；System 消息不产生任务。
2. 同一条消息多次提及同一 AI，只产生一个任务；不同新消息的提及分别建立任务，不因参与者或内容重复而合并。
3. 同一消息提及多个 AI，各目标拥有独立任务、上下文和队列。AI 自我提及与相互提及遵守相同规则。
4. AI @Human 作为普通消息提及保留和展示，不创建 AI 任务，不表示平台判定业务完成，也不引入站外通知。
5. 请求重试、重复事件和回复重放依靠幂等及唯一约束去重；这些技术重复与合法的新一轮讨论必须区分。
6. 每个 AI 按消息 Sequence 排队。失败重试有界，耗尽后保留失败队首并等待有效 Agent 显式重试，不能跳过任务；该规则属于执行可靠性，不是业务循环保护。
7. 既有认证、加入防刷和输入校验继续有效。本主题不增加按协作链统计的速率、深度或任务预算限制，也不引入整场会议的协作暂停状态。

### 2.1 外部停止后的平台行为

人类停止外部模型执行不一定会立即关闭 MCP 连接或宿主续租。平台只能依据真实传输状态、租约和工具调用更新状态，不能把“用户在外部点击停止”推断为立即离线或任务完成。

连接关闭或租约失效后，沿用主题六保留参与者及未完成任务；新的有效提及仍可为离线 AI 排队，恢复或接管后按既有规则继续。平台不会因外部停止而删除任务、重置重试次数或创建新参与者，也不会自行启动外部 Agent。仍在续租的宿主可能继续呈现处理中，这不表示平台能够获知模型内部进度。

会议删除仍是已有的独立生命周期操作：删除屏障建立后，所有会议访问和业务提交被拒绝。它不等于终止外部工具已在执行的工作。

## 3. 协作来源与标识

协作标识仅用于追踪任务因果关系，不承担业务状态机、完成判定或调度预算功能。保留轻量来源字段，不建立 Open/Paused/Completed 协作链实体或独立决策表。

| 字段 | 语义 |
| --- | --- |
| ChainId | 采用根 Human 消息的稳定 MessageId，表示同一次人工提及派生的来源链 |
| ParentTaskId | 产生当前触发 AI 回复的父任务；Human 根任务为空 |
| TriggerMessageId / TaskId | 沿用既有稳定消息和任务标识 |
| SourceAuthorKind / SourceParticipantId | 沿用已有触发消息作者信息 |
| ReplyMessageId | 沿用任务保存的回复消息，用于从 AI 消息反查来源任务 |

每条有效 Human @AI 消息建立新的来源链；同条消息的多个目标共享 ChainId，但各有任务和幂等键。Agent 回复所触发的任务继承来源任务的 ChainId，并以来源任务为 ParentTaskId。来源由服务端从已授权任务确定，客户端不能指定或修改。

新的 Human 提及使用新的 ChainId，即使继续相同话题也如此。这个标识不表示新的业务项目或审查轮次，原讨论历史仍按上下文规则可见。不保存用于截断的 Depth 或任务总量计数。

两个分支分别 @同一 AI 时，不同 TriggerMessageId 产生两个任务，按 Sequence 排队；重复投递同一触发消息则命中同一个任务。

## 4. 持久化调整

沿用 Domain、Abstraction、Application、Repository.Sqlite、IUnitOfWork 和会议事务边界。

- AgentReplyTask 增加 ChainId、ParentTaskId；其余任务状态、候选范围、确认、重试、幂等和尝试字段保持主题六语义。
- 在任务表的非空 (MeetingId, ReplyMessageId) 上建立唯一约束，保证一条 AI 回复只有一个来源任务，并提供反查索引。沿用 ReplyMessageId，不再增加独立 AI 消息来源表。
- 增加 AgentCollaborationBoundary：每会议一条 MeetingId、AgentTriggerStartSequence，保存启用 Agent 相互触发的消息边界。边界以服务端 Sequence 表达，之后仅序号大于边界的 Agent 消息可创建任务；Human 任务不受该升级边界过滤。

新增约束：ChainId 引用同会议 Human 根消息；ParentTaskId 非空时引用同会议、同链父任务。Active 会议中，Human 根任务必须满足 ParentTaskId 为空且 ChainId=TriggerMessageId；Agent 派生任务必须具有非空 ParentTaskId，父任务的 ReplyMessageId 必须等于子任务 TriggerMessageId。父回复的 Sequence 必须晚于父任务触发 Sequence，保证因果关系向前。

同会议、同目标、同触发消息的任务唯一约束保持不变。ChainId、ParentTaskId 创建后不能由重试、恢复或接管改写；跨会议或错误来源由复合外键及必要的 SQLite 归属触发器拒绝。

唯一的父任务引用解除例外是会议已持久化为 Deleting 后的内部删除清理：清理服务必须在现有删除事务中复查会议状态，再将 ParentTaskId 从非空置空；已为空的引用允许重入。此时保留 ChainId、触发来源和其他业务身份不变，空父引用不表示任务变成人类根任务。ParentTaskId 的物理列允许为空，非空引用的复合外键始终生效；Agent 必须有父任务及父引用不可改写的规则由读取会议状态的 SQLite 触发器校验，不使用会阻止合法清理的无条件非空 CHECK。触发器只放行 Deleting 下的引用清空或不变，不允许替换父任务、恢复已清空引用或新建任务。应用层同时限制该例外只能经删除清理事务执行。

任务完成、ReplyMessageId、回复消息、提及和持久化消息事件同事务提交。消费者只能观察到已提交的完整来源，不依靠进程内映射或正文猜测。

### 4.1 映射与数据库完整性

AgentCollaborationBoundary 使用 Guid ID 主键、MeetingId 唯一索引及指向会议的 Restrict 外键；AgentTriggerStartSequence 为整数，CHECK 范围为 0～9007199254740991。仓储返回可空实体，明确区分“未找到行”和“找到值为 0 的行”。Active 会议进入有效 @AI 任务分配时必须有边界行，Human 也检查行存在，但不按边界数值过滤。任务 INSERT 触发器同时校验会议 Active、边界存在，以及 Agent 触发消息 Sequence 大于边界。

父引用采用 (ParentTaskId, MeetingId) → AgentReplyTasks(ID, MeetingId) 的 Restrict 复合外键；MeetingId 保持非空并可与其他关系共享，同链关系由触发器检查。SQLite 在任一子键为 NULL 时不校验该复合引用，因此删除时仅置空 ParentTaskId，无需清空 MeetingId 或增加影子会议列。根 ChainId 通过复合外键保证同会议，Human 作者由触发器检查。来源作者、来源参与者、触发消息/提及及 ChainId 均不可改写；父引用仅有 §4 的删除例外。

把现有非唯一索引 IX_AgentReplyTasks_ReplyMessageId_MeetingId 替换为同名、同列顺序的部分唯一索引（WHERE ReplyMessageId IS NOT NULL）。它保证回复归属唯一；既有 (MeetingId, AgentParticipantId, TriggerMessageId) 唯一键保证触发去重，两者用途不同。保留原回复外键及被引用端候选键；子表索引不是外键有效性的前提。 任务范围查询使用 (MeetingId, AgentParticipantId, TriggerSequence) 索引；队首查询使用 (MeetingId, AgentParticipantId, TriggerSequence, ID) 部分索引，条件为 State 不等于 Replied 且不等于 Cancelled，避免扫描已终结历史。特定唯一冲突映射为 AgentCollaborationConflictException，再沿用 agent_operation_conflict；不得将任意约束错误吞成幂等成功。

任务表重建必须保留既有六个归属触发器：agent_attempt_owner_insert、agent_attempt_owner_update、agent_task_owner_update、agent_connection_owner_update、agent_retry_owner_insert、agent_retry_owner_update。迁移显式重建受影响触发器，验证 sqlite_master 名称、定义与实际行为，并执行 foreign_key_check。生产连接同步/异步打开后及初始化迁移前后均验证 PRAGMA foreign_keys=1，不满足时拒绝使用连接/启动；连接串 Foreign Keys=True 保留，不依赖测试连接的默认值。

## 5. 消息提交与任务创建

### 5.1 回复入口

可靠与 legacy 回复均先执行原有会议、连接、尝试、任务和幂等校验，通过 ResolvedMessageAppendCore 追加消息，再在同一事务将原任务标记 Replied 并保存 ReplyMessageId。回复重放返回原消息，不追加新的事件或下游任务。

无需新增完成、冻结或暂停工具。一次回复成功只表示消息和持久化派生入口已提交，不表示其他 AI 已收到、已回复或业务已完成。

### 5.2 消费者扩展

扩展 AgentMentionTaskConsumer，继续使用现有消息事件分发器和 agent-mention-task-v1 注册名。将 Human-only 条件扩展为 Human 或满足启用边界的 Agent，System 始终排除。

保留按目标 AI 补扫历史消息的方式：对事件涉及的每个目标，从该目标 AllocatedThroughSequence 后按 Sequence 扫描至事件位置，顺序补齐全部有效 Human/Agent 提及，不能只处理当前事件，以免事件乱序导致任务空洞。

处理每条候选消息时：

1. 复查会议 Active，读取已持久化提及；按目标 ParticipantId 去重，不重新用现在的参与者列表解析历史正文。
2. Human 消息以自身 MessageId 作为 ChainId。Agent 消息先检查升级边界，再用 ReplyMessageId 反查唯一来源任务，继承来源任务的 ChainId，并用来源任务 ID 作为新任务 ParentTaskId（不是复制来源任务自己的 ParentTaskId）。
3. 若任务已存在，沿用原任务及候选范围，不重复创建。否则以目标当前分配位置到 TriggerSequence 为固定候选范围创建任务，并推进 AllocatedThroughSequence。
4. 全部受影响目标的新增任务、分配游标和实际变化的 activity 在同一会议事务提交。失败整体回滚；重放由唯一约束与原事实收敛。
5. 提交后唤醒目标等待者。信号只用于通知，丢失后仍可从数据库领取任务。

不增加会议级保护计数或派生裁决高水位；各目标顺序由现有双游标和任务唯一约束保证。重复事件不能重复任务，较晚事件不能跳过较早提及。新入会 AI 仍从原子入会快照之后建立任务，不追溯入会前提及。

启用边界之后的 Agent 消息若没有唯一可信来源，视为持久化不变量损坏，保留失败事件并给出不含正文的诊断；不能伪造根链或静默跳过。事务失败不能推进目标游标。该故障按现有分发器恢复机制处理，不被解释为业务循环。

无有效 Agent 目标的事件直接结束，不补扫、不推进任何目标分配游标；消息仍保留在历史中，后续涉及该目标的有效事件才补扫其完整候选范围。无任务分配的短路不以边界缺失伪造边界 0。

Agent 来源反查还须验证会议 Active、来源任务 Replied、回复作者是该任务目标 AI，并按 SourceAuthorKind 分别验证 Human 根任务或 Agent 派生任务。合法 Human 根来源的 ParentTaskId 本来为空，不能用统一的非空条件拒绝它；Deleting 下解除的来源不能再次用于派生。

全目标单事务明确接受故障耦合：一个目标补扫遇到损坏来源，会回滚同次分配的其他目标。修复数据后重放原事件才是完整恢复路径；后续事件只有在某目标自己的候选范围不含损坏来源时，才可能独立补齐该目标，不能承诺高序号自动消除损坏。重试耗尽进入 Suspended 后不会自动恢复；运维先修复数据，再通过可信本地 DI 维护宿主按投递 ID 调用 IMessageEventRecoveryService.ResumeAsync，调用前在会议事务内复查 Active。现有服务无生产调用方，实施须提供此内部调用路径及验证；不新增网页/MCP 管理入口，也不用 retry_task 代替事件恢复。

### 5.3 上下文、并发与恢复

各 AI 继续使用独立的 AllocatedThroughSequence、DeliveredThroughSequence、连接字符预算和投递尝试。候选范围包含期间所有 Human、Agent、System 消息，完整保留触发消息并报告裁剪。来源元数据放在任务外层，不改变消息字符数格式。

一个 AI 正在处理时收到新的自我提及或其他 AI 提及，任务排在其现有队列后。跨来源链的新任务不能越过失败队首。连接停止、接管和服务重启不会改变来源，也不重建已回复任务。

沿用主题六的会议 gate、参与者协调及数据库事务锁顺序；消费者在既有会议事务中分配任务，不在持有发送者锁时等待目标外部执行。事务不跨网络、模型处理或长轮询。批量扫描可按有限批次执行，但事件只能在对应范围完整处理后确认完成。

activity 比较应按队首、连接和初始投递需要做有限投影，避免每事件额外枚举历史任务全表；候选消息和提及批量读取，避免逐候选 N+1。I03 用 10 个 AI、每目标 1 万历史任务及后续 100 个事件记录 SQL 次数、读取行数和事务耗时，确认 activity 读取不随历史任务量线性增加。此为实现效率验收，不是任务/轮数上限；不以超量中止合法协作。

并发回复区分同一有效尝试重放与新旧拥有者竞争：相同参数收敛为原回复，正文不一致沿用 reply_idempotency_mismatch，失效尝试/连接沿用 delivery_attempt_stale / connection_superseded。实际唯一竞争若未能收敛，返回既有 agent_operation_conflict；不能把可识别竞争暴露为通用不可用。不能为了重放绕过所有权及删除屏障。

## 6. MCP、参考 Agent 与网页

保留 agent-messaging-v1、现有工具名及两种可靠性模式。仅可靠模式 join/resume 的能力列表增量声明 multi_agent_collaboration_v1，legacy 不新增 capabilities 字段，其协作行为不依赖能力发现；任务外层和 get_agent_status 的既有任务摘要增加 collaboration 可选对象，包含 chainId、parentTaskId、sourceAuthorKind、sourceParticipantId。不改变已有 kind、nextAction、确认流程或错误形状。

旧客户端可忽略来源字段，仍能等待和回复；legacy 与 explicit_ack_v1 均可以被 Agent 提及，可靠模式的确认/接管门槛保持不变。只返回调用者自己任务的必要来源信息，不开放按任意 ChainId 查询他人任务和连接凭据的接口。

回复工具沿用“消息已接受，继续等待”的语义，不新增 pending/suppressed 派生决策协议。异步消费者负责可靠创建下游任务，reply 成功不承诺下游处理已完成。

驻留指令只说明通用交互：有效 @AI 可产生任务，普通消息不单独推送，回复后按原流程继续等待。指令不写入审查角色、冻结规则、固定协作轮数或需要何方同意。外部宿主继续负责模型执行与独立续租，是否停止由人类在外部工具中控制。

驻留模板分别使用 resident-instruction-v3-legacy 与 resident-instruction-v3-reliable，文本和版本一同更新；前置版本夹具保留 v1/v2。collaboration 缺省时省略整个字段，存在时根 parentTaskId 显式为 null；不增加来源显示名，触发消息 ID 复用现有任务字段，名称从授权上下文获取。工具总数仍为 9（4 个既有工具加 5 个可靠专属工具）。

网页复用 MessageTimeline、MessageComposer 和 ParticipantList，显示统一消息流、有效提及和真实在线/处理状态，不增加暂停按钮、冻结状态、业务完成标识或循环保护提示。AI @Human 使用现有提及展示；Agent 与用户自行解释消息内容。

消息按 messageId/Sequence 去重，activity 继续使用主题六 revision。刷新、重连、切会和删除后迟到消息按现有规则处理。HTTP/Kiota、SignalR 镜像和 MCP 契约分别验证，不为来源追踪建立新的消息通道。

## 7. 会议删除最终收口

### 7.1 访问屏障

复用创建者权限、Active→Deleting 持久化屏障和 MeetingDeletionRecoveryService。屏障建立后，历史读取、发送、订阅、MCP 操作、幂等重放、任务消费者、租约扫描和恢复入口都不得继续读写该会议。

业务事务先完成，则消息及派生资源全部纳入删除；删除先建立屏障，则业务不能提交。取消等待、清理注册及会议订阅，不等待外部模型完成，也不声称能终止平台之外的文件写入或工具调用。

删除确认仍明确全部会议内容永久不可访问。沿用主题三的异步删除契约：首次成功提交 Deleting 屏障后立即返回 202 Accepted，表示请求已接受且会议已不可访问，不等待物理清理完成；已进入 Deleting 或已经物理删除时返回 404 meeting_not_found，客户端均按会议已不可访问处理。屏障提交前失败沿用原错误契约，不伪报已接受；屏障提交后清理失败保持 Deleting，由后台恢复器重试，不回 Active。物理清理完成是独立验收条件，不能由 202 响应或页面消失推断。

### 7.2 清理顺序

在现有清理事务中扩展以下顺序。清理服务和恢复器事务内复查 Deleting 是本主题新增防护；当前代码仅有事务/存在性检查，不能当作已经实现：

1. 在删除事务内复查会议已为 Deleting，取消未完成任务，清空 CurrentConnectionId、CurrentAttemptId、ReplacementAttemptId、SupersededByConnectionId，并按 §4 的删除例外清空所有任务的 ParentTaskId 同表引用，包括已回复任务。引用解除和后续物理删除处于同一事务，失败整体回滚。
2. 删除恢复收据、初始投递和任务尝试，再删除所有回复任务、上下文游标及连接。任务删除须先于其 ChainId 引用的根消息和 ReplyMessageId 引用的回复消息。
3. 删除 AgentCollaborationBoundary，再按原顺序删除消息事件投递、消息事件、提及、消息、参与者和会议。

清理覆盖全部历史及当前状态，不只清当前连接或未完成任务。新增字段与表都有会议归属，保留平台用户和其他会议。

屏障提交后或清理中崩溃，由启动恢复器继续处理 Deleting。清理事务回滚后可重入，不能因恢复器、消费者或通知补发使会议复活。新增来源引用须在真实 SQLite 外键启用条件下验证。

删除前已发送的网络字节不能撤回，客户端丢弃迟到的旧会议事件；屏障后禁止新读取和提交。删除通知丢失时，刷新或重新订阅以服务端状态为准。另一会议的聊天和 AI 任务不应因外部长任务或通知失败被全局阻塞。

## 8. 升级边界

采用单实例停机升级：先停止全部旧版本业务写入进程及事件分发器，确认退出，再由新版本执行迁移；迁移完成前不启动业务入口和分发。禁止新旧版本重叠写库，不能只依赖 SQLite 写锁。在迁移事务中保存所有现存会议（包括 Deleting）消息表已持久化的最大 Sequence 为 AgentTriggerStartSequence。空会议边界为 0；部署本主题后新建会议同样从 0 开始。保留全部原任务、幂等键、候选范围、确认、尝试和回复事实。

- 已有 Human 触发任务以原 TriggerMessageId 回填 ChainId，ParentTaskId 为空；同条消息多目标共享来源。
- 已回复任务继续使用原 ReplyMessageId；先校验唯一来源和会议归属，再建立约束，不根据正文推测关系。
- 旧 Agent 消息无论其事件是否消费、是否被较新事件补扫，都因固定边界而不追溯创建任务。过去保留的 AI 提及不能在升级后突然启动协作。
- 升级前尚未消费的 Human 消息仍按原游标补扫和分配，不按新的 Agent 边界过滤，不直接推进游标吞掉待处理任务。
- 旧未完成任务在升级后产生的新回复，序号大于边界，正常继承回填来源并触发目标；重放旧回复仍使用旧序号，不产生新任务。
- Deleting 会议继续删除，不需要先派生业务任务；正常迁移同样建立边界行；缺行仅作为异常/恢复测试夹具，清理仍应可重入。

迁移审计还检查：Replied 的 ReplyMessageId 非空且存在；所有非空回复由 Agent 所写且作者参与者等于任务目标；TriggerMention 属于 TriggerMessage 且提及目标等于任务目标；触发作者及会议归属一致。审计先于约束建立和数据搬迁，不自动修补损坏事实。

迁移遇到跨会议关联、多个任务指向同一回复或无法证实的旧任务来源时中止并报告标识诊断，事务回滚，原库仍可由原版本读取。连接模式不因本主题升级改变，可靠参与者不能降级。

[测试计划](testPlan.md)覆盖下列范围；本设计不将任何项目标为已通过。

| 范围 | 必须验证的结果 |
| --- | --- |
| 多 Agent 交流 | Human→A→B、A→B→A、同条多目标、自我提及、新消息重复提及均按规则建任务；System 不触发；AI @Human 只展示 |
| 多轮持续协作 | 使用有限的多轮、多分支脚本场景，证明平台没有轮数、累计任务数或重复参与者截断；测试宿主自行停止 |
| 幂等与顺序 | 回复重放、重复/乱序事件、事务重试不重复任务或消息；补扫无遗漏，每个目标按 Sequence 排队 |
| 上下文 | 不同预算独立裁剪；包含期间各类消息，触发消息完整；来源字段不改变上下文字符数语义 |
| 来源约束 | 根消息、多分支、父任务、回复关联正确；外部伪造、跨会议来源和无来源 Agent 消息不能被静默接受；Active 下清空或替换父引用被拒绝，Deleting 下仅允许内部清理解除引用，不允许恢复、替换或新建任务 |
| 外部停止 | 关闭传输或停止续租后按真实状态离线；只停模型但保持续租时不伪报离线；未完成任务保留，恢复/接管继续 |
| 可靠性 | 失败重试有界、耗尽队首阻塞、显式重试与接管不改变来源；停止期间新提及仍排队 |

| 升级 | 空库、旧库副本、未消费 Human、旧 Agent 提及、旧任务新回复与旧回复重放；边界正确，无追溯派生或任务丢失 |

| 回归 | 登录与现有账号维护、会议创建/加入/切换、Human 群聊、AI 可靠恢复、刷新重连及删除后迟到事件隔离 |
