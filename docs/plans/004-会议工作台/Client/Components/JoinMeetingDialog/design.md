# 加入会议对话框设计

## 1. 组件职责

`JoinMeetingDialog` 负责会议码预检、显示名称确认和最终加入。它不保存跨会话凭证，不决定成员授权，不把会议码写入 URL 或 localStorage。

## 2. 步骤

### 输入会议码

提供会议码单行输入。客户端输入或粘贴后只去除首尾空白，按标准 GUID `D` 格式解析并以小写 `D` 格式展示，大小写不敏感；内部空白、缺失连字符、其他 Guid 格式或非法字符不自动修复，其他情况给出字段错误。输入值只保存在对话框内存状态，服务端重复执行最终规范化和校验。

### 预览确认

预检成功后展示会议名称和可选背景，并填入当前账号昵称作为默认显示名称。已加入时展示既有显示名称并提供直接打开会议动作，不允许编辑原身份。

### 最终加入

用户可以修改默认显示名称。客户端以 Trim + NFC 后长度不超过 64 作为即时校验，不依赖原始输入长度；服务端负责最终规范化、64 字符上限、比较值 128 字符上限和唯一性校验。提交时再次发送会议码和名称。

## 3. 错误和状态

- 无效码或删除中：显示统一会议不可访问；
- 名称冲突：定位到显示名称字段并保留输入；
- 限流：读取 `Retry-After`，提示可再次尝试的时间并保留会议码；不显示剩余次数；
- 网络错误：提供重试，不把请求显示为已成功。

关闭对话框时清除会议码、预检结果和显示名称，避免敏感值残留在 feature 状态。

## 4. 可访问性

步骤标题、当前步骤和错误可被读屏识别；名称输入支持键盘提交和取消；会议码输入不自动写入浏览器历史。
