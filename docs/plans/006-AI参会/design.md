# Agent参会：MCP试用与官方CLI设计

## 1. 范围与依据

承接增量FR-003、FR-009、FR-015、FR-016、FR-017；官方CLI是后续正式接入目标；CLI交付前提供本文末尾定义的MCP试用入口。复用[005消息与附件](../005-实时群聊/Server/design.md)、[007可靠连接](../007-AI任务连续性与接管/design.md)和[004参与权限](../004-会议工作台/Server/design.md)。CLI不执行模型、不生成回复任务，不要求Agent阅读ACK，MCP试用接入指南见ReferenceAgent；CLI后台和本地检索仍为待实现范围。

## 2. 前台、后台和会话

采用同一安装的前台可执行文件与按当前操作系统用户运行的后台进程。前台经本地IPC调用后台；Windows使用当前用户ACL限制的命名管道，Linux/macOS使用仅当前用户可访问的Unix socket，不开放公网控制端口。后台独立维持连接，前台命令结束不结束参会。

每个本地session独占其server、meetingId、participantId、连接凭据、同步位置、前台获取位置及待发送记录；所有参会命令显式指定--session，避免多Agent共享安装时隐式使用“当前会话”。已绑定会话不能用join覆盖另一会议，返回session_bound并要求另取会话名。会话名称只是本地定位键，不作为远端身份。

启动后台仅准备服务，不恢复远端连接。进程或电脑重启后由Agent显式reconnect；运行中短暂网络失败遵循007自动恢复。disconnect仅停止指定会话。后台崩溃恢复先读取本地持久状态，不生成新参与者。

## 3. CLI目标命令契约

以下为待实施命令，不代表当前安装包已经提供。统一JSON输出，正文与元数据分开；--help及参数错误提供中文解释和可执行示例，示例不含真实凭据。

| 命令 | 关键参数 | 输出与语义 |
| --- | --- | --- |
| version / capabilities | 无 | 版本、系统/架构、协议和能力；不联网入会 |
| start | 无 | 启动或定位后台，不自动重连 |
| join | --session、--server、--meeting-code、--name | 明确加入；返回身份、快照、初始历史和同步状态 |
| reconnect | --session | 恢复原身份，退出不恢复参与，删除不得恢复内容 |
| takeover | --session、--server、--meeting-code、--name | 显式接管Agent身份；区别于join |
| read | --session、--cursor/--max-chars可选 | 从前台完整获取位置按本人可见序号读取新消息 |
| wait | --session、--mentions-me、--timeout可选 | 公开@自身及发给自身的私聊均可返回；超时idle |
| history | --session、--after或--before或--cursor、--through/--scope/--peer可选 | 独立历史查询，返回分页/续读位置，可重复 |
| send | --session、--text或--text-file、--reply-to、--private-to或--public可选 | 无回复默认公开；回复继承原范围；私聊指定目标ID；reply-to不是任务凭证 |
| upload / download | --session、--file 或 --attachment-id、--output | 上传暂存附件、下载授权附件到本地 |
| send | --session、--attachment可重复 | 绑定已上传附件，可与正文合发 |
| attachments | --session、--cursor/--scope/--peer可选 | 授权附件列表、消息定位 |
| search | --session、--query、--sender/--from/--to、--scope/--peer可选 | 关键词+向量混合结果、原文标识和同步/索引范围 |
| show | --session、--message-id、--context可选 | 展开原文和邻近消息，仍受输出预算 |
| status / diagnose | --session、status支持--refresh | 连接、同步、索引、待确认发送；refresh可只核验生命周期而不重连 |
| probe | --session、--participant-id | 服务器主动探测目标CLI，结果不表示模型工作 |
| leave | --session | 明确退出参与关系，固定历史上界 |
| disconnect | --session | 停止本会话心跳、监听和自动重连，保留历史 |

默认max-chars=100000，允许1—100000之间主动调小；非法值指出参数、允许范围及示例。正文与text-file互斥；空正文且无附件拒绝。wait默认25秒，允许1—60秒，本地有界等待结束不影响后台接收。凭据参数支持私有文件或标准输入，日志/诊断不回显会议码及恢复凭据；文档命令仅使用占位符。

## 4. 内部服务协议与容量

后台采用版本化HTTP JSON命令和有界长轮询接收，复用ASP.NET Core宿主，不向宿主暴露MCP。目标协议前缀/api/agent/v1；操作契约由007定义。join/takeover通过POST提交会议码和预先落盘的恢复凭据；其余命令使用后台私有的Bearer连接凭据和代次。history/search下载授权使用会话的历史访问凭据，与活跃连接资格分开；disconnect不销毁历史读取凭据，leave收紧其可见上界，删除撤销内容访问资格。每次历史请求仍查服务端参与关系和当前参与者代次，不只相信凭据中的旧范围。显式接管撤销旧代次远端历史资格；断开、退出则按007保留受限历史资格；删除后仅保留004删除状态专用凭据。

接口映射：POST /join、/reconnect、/takeover、/heartbeat、/acknowledgements、/disconnect、/probe；GET /status、/messages（游标）、/submissions/{id}；POST /messages、/attachments；GET /attachments及/attachments/{id}/content；POST /leave。消息和附件形状复用005，服务器解析受信Agent身份后调用同一应用服务，不复制另一套消息存储。

长轮询响应分messages与controls两个信封；controls包括心跳/主动探测挑战、删除进行中/已完成、退出和连接取代通知，遇控制信号立即唤醒，不等待25秒满。控制处理不受模型读取、历史回补或向量索引队列阻塞，控制信封不进入聊天原文或正文预算。长轮询默认25秒，取消只结束当前等待，不退出会话。协议不支持或服务版本不匹配返回明确错误，不回退宿主MCP。传输字段及OpenAPI由实现时服务端生成，以上为目标契约。

字符预算以Unicode标量值计数（一个补充平面字符算1），仅统计返回正文，不统计ID等元数据。单条消息超过剩余预算按字符偏移分段，返回messageId、sequence、contentOffset、nextContentOffset、complete和nextCursor；不可截断后直接跳到下一条。完整接收与前台截取分离，后台分页保存全部原文。会话默认输出100000，不改变服务端原文，也不作为消息存储上限。

普通read的nextCursor仅在一次输出写出成功后保存；进程崩溃允许重复输出，不允许跳过。wait维护独立关注筛选位置（公开@自身或发给自身的私聊）；history/show不改变增量位置。每次输出包括候选范围、实际范围、hasMore、继续位置和授权上界。入会最近历史只用于首次输出，后台仍分页同步全部有权历史。

### 4.1 私聊命令与范围

send --private-to <participantId> 在当前会话会议内向唯一对象发送；--public与--private-to互斥。--reply-to引用私聊时默认继承原双方；正文@不改变目标。若用户明确选择--public，以新的公开发送意图提交，去掉私密引用且不自动复制原正文或附件；冲突的显式私聊对象报参数错误。发送载荷持久保存visibility和recipient，重试不能因当前页面/后续命令切换改变范围。

read/history/search/attachments支持--scope all/public/private及--peer，默认all仍仅含本人有权消息。输出逐条标注visibility、发送者与私聊对方。wait --mentions-me把发给自身的私聊视为命中，不要求正文@；自己发送的私聊不因收件人条件返回，第三人私聊不得影响返回/计数。无论命中何种消息，Agent自主决定回复，不保证宿主自动唤醒。仅过滤前台输出，不改变read位置；所有位置使用005本人投影序号，不能用全局序号缺口补取无权消息。

## 5. 本地原文与混合检索

选择SQLite作为本地原文与索引目录存储，按session隔离数据库，用户私有目录保存。Messages以(serverId,meetingId,messageId)唯一，保留本人sequence、visibility、recipientParticipantId、发送者快照、完整正文、时间、提及及附件引用；正文是事实副本，不以摘要或向量替代。附件默认保留引用，download明确保存二进制，不把所有附件自动下载作为全文同步前提。

SyncState保存授权高水位、join快照基线S、S之后连续落盘位置及0至S回补区间；实时优先、历史低优先分页回补，恢复不能丢弃已建立范围。SyncState同时保存协议与投影版本；旧全局游标不能用于本人序号，升级按005规则重建范围并按消息ID核对回补。IndexState记录模型标识/版本、已索引范围和失败。消息落盘与同步位置同事务；索引在独立队列后台更新。FTS5 trigram建立中文子串关键词索引；不足3个Unicode字符的查询改用参数化原文子串扫描，消息标识直接查主键。输入作为字面查询转义，不让用户原句变成FTS运算符；能力探测不支持FTS5时保留原文扫描并提示降级。该边界依据[SQLite FTS5官方说明](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)，具体捆绑版本需在打包时验证。向量按消息分块保留原文偏移；首版小规模向量可在本地顺序计算相似度，达到实际瓶颈后再决定扩展索引，避免把扩展库当成可用性前置。

混合查询先限定会话、会议、时间、发送者和授权上界，再分别取关键词/向量候选，以排名融合合并（设计默认RRF常数60），按messageId去重并保留命中片段。show从原文表在同一公开或同一双方私聊范围展开前后文，默认不把私聊片段拼到公开回复上下文。输出包含同步范围、索引范围、是否降级；无结果不能声称完整服务端历史中不存在。

向量默认在本机生成，采用可单独下载的版本化ONNX模型包及本地推理适配器。模型包清单声明license、校验值、维度、最大输入和运行要求；具体模型及最低硬件尚需中文检索与三系统打包实测，未通过前向量项不能标为可交付。原文不发送远端生成向量。首轮评估使用隔离的中文样本：原句/短词/标识、语义改写、否定与易混概念、跨会相似文本，逐项标注相关消息，比较关键词、向量及融合Top-10的召回与来源正确性；资源记录峰值内存、索引时间和收发延迟。可接受质量/资源阈值根据真实候选实测写入发布验收，不凭空承诺效果。下载失败、模型缺失、资源不足或索引损坏时关键词/原文仍工作；限制索引单worker及批次内存，不抢占收发。更换模型旁路重建索引，原文不重写。

## 6. 权限和异常

历史查询、检索、附近上下文、附件清单和下载统一应用004授权上界与005私聊双方范围。leave后更新本地权限记录再停止同步，任一方退出均暂停该双方新私聊发送，不以旧索引扩权；明确重入成功后更新权限并回补离开期间历史。离线查询显示最后确认的权限与同步范围；用户另存文件、复制内容及Agent已有上下文不保证收回。会话A不能经参数引用会话B数据库或凭据。

磁盘满时接收落盘失败不得ACK，报告存储错误并停止推进同步位置；恢复空间后按最后连续位置重投。向量错误只影响向量搜索。参数错误与网络、服务授权和存储错误分开，返回code、field、reason、allowed、example及retryable。

### 6.1 会议删除与受管副本清理

首次join或takeover为本地会话生成独立lifecycleProof并随握手登记，保留与活动连接分离的删除状态查询资格，具体生命周期契约见004。收到可信meetingDeleted控制，或重新联网通过生命周期查询确认deleted后，先持久化本地删除标记、关闭查询与索引入口，取消本会议收发/历史/下载/索引任务并递增generation，再清除受管数据。联网恢复先核验生命周期，再允许远端补取；已主动断开或被接管的会话不自动参会，可由显式status --refresh执行仅生命周期检查。网络失败、404/401或superseded不是删除确认。deleting先封锁查询并显示处理中，确认deleted后执行清理。

本地按serverId+meetingId遍历当前用户后台管理的全部session：删除完整原文、关键词/向量索引及分块、受管附件缓存、包含正文的发件箱/草稿和临时下载。一个会话收到确认，不允许同一安装内另一份该会议索引继续返回内容。会话凭据和游标移除，只留不含正文/参与对象的清理标记及必要删除确认信息。用户通过--output另存的文件不扫描或删除；受管缓存与用户另存目录必须在命令及存储布局中明确区分。

SQLite会话专用数据库关闭句柄后删除数据库、WAL/SHM和索引文件；后台任务必须检查删除代次，禁止完成后回写已删正文。占用或磁盘错误时保持入口封锁并报告清理未完成，后台重试，重启先恢复清理，全部成功后才报告本地清理完成。旧缓存迁移副本也纳入受管清单，不保留带原文的自动备份。此清理不承诺物理介质取证擦除，不控制用户自行备份或Agent已有上下文。

离线期间不能即时获知删除；仍按最后已确认权限显示离线范围。联网确认后不再返回被删内容，迟到网络/索引结果被generation丢弃，不从旧文件或模型向量自动重建会议。其他会议与用户另存文件保持不变。

## 7. 发布与指南

服务端、Web、CLI、技能、指南、安装脚本、manifest和校验文件保持统一releaseVersion；版本化下载路径及latest由[Server设计](Server/design.md)承载。先读latest清单固定版本，再下载对应材料，不能混用安装脚本和二进制版本。

首批覆盖Windows、Linux、macOS。发布验证候选矩阵为Windows x64、Linux x64/arm64、macOS x64/arm64；最低系统版本、Linux glibc基线及Windows arm64是否提供原生包须由实际构建和安装测试确定，未通过不得在manifest标支持。不把这些候选写成已发布事实。

通用指南维护在[ReferenceAgent](ReferenceAgent/README.md)，覆盖安装、入会、读取、发送、附件、检索、重连和断开。邀请引用同版指南，说明准确参与者名称、宿主授权、凭据误发后外部撤销/轮换；不增加敏感信息自动拦截。

## 8. 交接限制

消息和连接使用现有手写分层扩展，本轮不计划业务代码生成，不生成客户端或修改数据库。开发前必须核对真实包契约及旧数据库升级可行性；具体向量模型、支持矩阵和持续运行指标以测试证据补齐。实现步骤见[impl](impl.md)，验收见[testPlan](testPlan.md)。

## MCP试用版接入

### 官方接入脚本

CLI交付前，官网随Web静态资源提供版本化单文件 `agent/0.1.0/roundtable-mcp.mjs`。运行环境为 Node.js 20.3.0 或更高版本，无第三方npm依赖；可由Agent持久JavaScript环境导入，也可作为前台JSON Lines进程运行。脚本负责MCP传输、身份状态、分片游标、独立续租与发送幂等；模型负责理解和回复，脚本不自动生成或发送回复。脚本使用指南与脚本同版。

每个身份使用独立私有状态目录和独占锁；状态原子保存，保留身份凭据、读/等待两套游标、完整收件箱、未完成片段及发送前落盘的发件箱。读取结果保存后才推进游标；宿主可再次读取收件箱，避免输出丢失造成漏消息。重试发送复用持久化的UUID及完整载荷，未知结果先查询提交状态。长等待仅串行执行，续租独立进行。

首次create；恢复必须显式reconnect并创建新transport；不自动takeover，不自动leave。进程退出停止续租并尽力disconnect；退出进程不保证远端即时离线，持久化状态保留。此脚本不是CLI后台服务，不承诺宿主模型自动唤醒、全文检索或所有系统兼容。脚本本地文件包含会议资料，保存在用户私有目录；不得提交或放入官网资源目录。

附件使用同源短期凭据，拒绝跨源地址和重定向；下载到显式本地目标，凭据不输出。测试涵盖HTTP/SSE响应、分片恢复、幂等发送、独立续租及实际部署服务；发布到官网另按部署授权执行。

官方CLI仍是后续目标；在CLI交付前提供MCP试用入口/mcp，协议participant-sequence-v2，服务版本mcp-preview-v2。它读取本人可见消息投影，不恢复提及任务、强制回复、阅读ACK或旧全局序号。旧工具wait_for_mention/reply_to_mention不再公开，旧客户端必须按新工具清单接入。

工具覆盖加入/显式接管、会议信息、历史读取、单条消息、等待新消息、发送及发送结果核对、附件清单/传输准备、生命周期状态/续期、断开与退出。无回复默认公开；回复未指定范围时继承原范围。私聊和附件沿用005权限，第三人不可获得正文、元数据或高水位变化。MCP transport与connectionSessionId双重绑定，外部参数不得指定作者身份。一个transport只绑定一个会议身份。

读取按本人投影序号分页，明确返回续读位置；单次正文预算默认100000 Unicode标量，长消息分段并返回偏移，只有完整消费后推进下一消息位置，不能静默裁剪。wait默认25秒、最长60秒；mentionsOnly只过滤公开@自身及发给自身的私聊，过滤不代表其他消息无权读取。idle不是退出指令。

附件采用MCP工具签发短期、绑定当前连接的传输凭据，通过专用HTTP流式上传/下载，大小仍按100000000字节部署上限执行；凭据只放Authorization头，不进入URL/日志。文件统一下载，由Agent使用自身文本、图片等能力理解，平台不做OCR、图片解读或文档解析。工具不接受服务器本地文件路径，不从任意外部URL抓取。附件上传成功后由send_message绑定，未绑定不可下载。

试用不包含系统级自启动、本地原文/向量检索、三系统CLI安装或自动心跳主动探测验收。仅宣称实际验证的MCP宿主、传输、消息及权限范围；MCP连接结束保留参与身份，显式退出保留既有历史上界，删除终止全部内容访问。发布包与真实Agent试用验收分开判定。

## 点名参与与自由讨论

默认邀请将可复用的站点配置与本场私有邀请分开。多会议入口固定使用 X-RoundTable-Mode: rooms；attend 返回受保护的房间凭据，next 同时等待传入的多个房间，回复、附件与退出操作均按房间隔离。模型使用 attend、next、reply、skip 和 leave。服务端在活跃操作中维护五分钟租约；长等待通过 MCP ping 确认宿主仍在通信，超时返回 idle。更换传输后继续交付尚未回复或跳过的消息。创建者身份由服务端确认。

兼容脚本入口提供独立命令 next。每个身份由一个本地进程持有会议连接，宿主通过带私有凭据的本机命令通道阻塞取件、下载、回复或跳过。下载默认保存到该身份的会议附件目录。服务端创建、脚本收齐、命令交付和服务端接受回复分别标时。脚本持久化待处理消息与回复编号，按条向宿主交付完整点名或私聊，保存回复或跳过的结果后继续。宿主负责向模型派送事件。等待命令仍活跃时允许跨租约静默。脚本每 60 秒续租，等待消息也会续租。服务端默认每 5 秒复核 MCP 连接，最后一次续租后 5 分钟仍无心跳，即将该连接置为离线并推送至已打开的工作台。成员身份保留，已替换的旧连接不能影响新连接。失去取件者且连续五分钟无操作时脚本临时断开并保留待处理消息。创建者的明确退会请求使用服务端身份判断。正式退会以 left 回执为准，释放监听和本地锁，再次获邀显式重入。手动协议入口供需要细粒度控制的宿主使用。

第二阶段由主持人切换会议参与模式。自由讨论将短时间内的普通公开消息合并，点名与私聊单独优先交付。模型可选择沉默。准备主动发言期间若出现新公开回复，应在发送前复核，避免重复表达。切换模式以生效时的位置为界，避免把既有公开历史集中交给模型。
