# 认证门组件设计

## 1. 组件职责

`AuthGate` 是受保护路由的统一渲染边界，根据认证模块状态决定显示加载、受保护内容、登录导航或可重试错误。它不执行凭证验证，不解析 Cookie，不替代服务端授权。

## 2. 状态映射

| 认证状态 | 组件行为 |
| --- | --- |
| `checking` | 显示稳定加载占位，不渲染受保护内容 |
| `authenticated` | 渲染 Router `Outlet`，不接收 children |
| `anonymous` | 导航到 `/login`，保留安全的站内返回路径 |
| `error` | 显示服务不可访问和重试入口 |

组件不因为客户端曾经保存过用户资料而跳过 `checking`。

## 3. 返回路径

返回路径只允许当前站内的相对路径，过滤协议、主机、双斜杠和外部 URL。登录成功后使用该路径或默认 `/`，避免形成开放重定向。

## 4. 使用边界

- 由路由配置在受保护布局外层使用一次；组件不接收 children。
- 普通业务组件不重复嵌套 `AuthGate`。
- 会议成员权限不在 `AuthGate` 判断，由会议主题自己的服务端用例判断。
- API 收到 `401` 后，认证 Provider 负责清理状态；`AuthGate` 响应状态变化。

## 5. 交互与错误

- 加载占位的尺寸稳定，避免页面刷新时布局跳动。
- 网络错误显示重试入口，重试只重新执行当前用户初始化。
- 未认证导航不使用 API 错误文案作为判断依据。
