# 多 Agent 自由交流与关闭、退出集成设计

## 1. 主题定位

依据增量 FR-011、FR-015，复用[004生命周期与权限](../004-会议工作台/Server/design.md)、[005统一消息与附件](../005-实时群聊/Server/design.md)、[006官方CLI](../006-AI参会/design.md)和[007可靠连接](../007-AI任务连续性与接管/design.md)。保留现有目录，负责跨主题集成，不另建任务、协作链、删除协调器或业务模型。

## 2. 自由交流

Human、Agent通过同一追加核心发言，系统消息进入同一历史。Agent不需要先领取提及任务，可以自主发送或回复。@记录只确定关注对象；提及自己、多人、引用或未提及均不产生必须行动的要求。平台不要求轮流回应，不推断责任、完成、思考或冻结状态。

每个CLI后台独立收取全部授权消息；前台可筛选提及自己的消息，也可按位置读取全部新消息和历史。筛选不推进全部消息获取位置，不影响其他会话。没有队首失败阻塞，不因未回复丢弃后续消息。

## 3. 关闭、退出及历史

004是唯一生命周期规则来源。本主题检验以下组合：

- 创建者关闭会议后，所有活动连接停止收发、活跃列表移出；原成员从历史入口查看各自授权范围，附件与消息一致。
- 非创建者退出只终止自己的参与，固定退出时的历史上界；其他参与者继续交流。
- 明确重新加入开放会议才扩大至完整历史；普通重连、接管或搜索不得扩大范围。
- 创建者退出请求被拒绝，不隐式关闭。断开只离线，活跃列表仍保留。
- 广播和状态通知不是权限来源；丢失通知后由下一次请求、订阅或状态查询收敛。
- 已发出的网络字节不能撤回；客户端收到关闭/退出后丢弃超过授权边界的迟到数据，服务端不再签发新的越界读取或下载。
- 不物理清理会议、参与者、消息、附件；不恢复旧Deleting清理任务。

## 4. 组合时序与故障

发送、退出、关闭共享004短事务边界：发送先提交则进入退出/关闭时的高水位；退出/关闭先提交则新发送被拒绝。发送响应丢失时仍通过原clientSubmissionId核对，不因会话终止重复追加。

发送附件先完成005暂存，再在同一消息提交中绑定；关闭发生在绑定前则拒绝消息提交，暂存按未绑定规则处理，已绑定附件永久保留。历史下载与本地检索使用同一权限高水位；搜索不能以旧索引返回退出后的消息。

连接替换与关闭/退出并发时，关闭或退出一旦提交，新连接不能恢复活跃收发。迟到心跳、ACK和重试以连接代次校验，不影响新连接，也不扩大成员权限。

## 5. 迁移与范围

本主题不继续维护旧任务来源链、AgentCollaborationBoundary、任务父子引用及物理删除收敛方案。实施时按007迁移边界核查旧表与后台消费者；保留历史消息身份、排序、作者、附件与发送回执。对已物理删除资料不承诺恢复。

端到端测试由本主题组织，各模块修复回到原负责主题；不复制一套API与状态机。只有真实浏览器、两个独立CLI会话及进程故障组合验收完成后，才可声称业务闭环验证；本次仅文档设计。
