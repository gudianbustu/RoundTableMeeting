# 会议工作台客户端设计

## 1. 责任与入口

沿用React Router、Ant Design、feature适配层、AuthenticatedLayout与Kiota生成客户端；页面不直接依赖生成模型。路由保留/meetings/:meetingId，按详情权限呈现活跃或只读历史；导航提供活跃/历史分组，无须给历史创建另一套会议身份。

[服务端契约](../Server/design.md)是状态和权限来源，客户端不根据创建者图标或连接状态推断历史授权。

## 2. 状态与加载

状态按meetingId隔离，包括active/history列表、详情、permissions、revision、当前操作及错误。加载、空列表、不可访问、网络失败分别展示。切会递增generation并取消旧请求；只合并当前meetingId及不旧于已知revision的响应。失败保留当前可用视图并允许重试，不用空列表伪装失败。

邀请信息只在弹窗打开时请求并短期保留内存；关闭、切会、退出或注销清空，不能进入URL或浏览器持久存储。普通详情不夹带会议码。

## 3. 创建、加入与编辑

创建沿用creationRequestId幂等，提交期间禁止重复点击；响应丢失复用原ID。加入先预览，再明确提交；left身份显示“重新加入”，成功后刷新权限和完整历史范围，普通浏览不触发join。

创建者编辑沿用会议名称与背景字段，发送expectedRevision；失败保留输入，409重新加载并提示冲突，不自动覆盖。用户未保存草稿不改变标题。成功后更新导航、详情和document.title。当前会议为“会议名称 - 圆桌会议”，无选择为“圆桌会议”，独立页面为“页面名称 - 圆桌会议”；新消息不追加数量或提醒。

## 4. 删除、退出与历史

创建者显示“移除会议”，确认框提示删除全部公开消息、私聊及附件，所有人不可再查看，并沿用输入当前会议名确认，不加额外确认步骤。非创建者显示“退出会议”，确认仅影响本人。服务端拒绝创建者退出时保留界面，不改成删除操作。

退出成功后刷新列表、转只读历史并停止本人订阅；保留有权公开记录与已有本人私聊。删除屏障确认后立即移出活跃/历史入口，清除本会议展示缓存、草稿、附件ObjectURL，未完成清理时显示删除处理中而非完成；状态查询失败允许重试。删除/退出通知丢失时后续状态或写请求错误触发重载。历史模式通过005读取授权消息和附件，禁用发送、邀请、编辑；会议开放且自己left时提供“使用会议码重新加入”。禁止自动调用join修复权限错误。

## 5. 组件与交互

布局沿用桌面左导航、主消息区、参与者侧栏；移动端导航/侧栏使用抽屉，保留焦点返回。头部操作使用清晰名称与aria-label。ParticipantList按online/offline分组，offline默认折叠；状态由服务端快照/增量更新，离线不删除名单。人类/Agent仅类型区别，无所属人和最后活跃。连接诊断不混进姓名。

消息滚动、附件与发送状态归005，工作台仅传入meetingId、权限及参与者目录。旧会议响应、标题、草稿或通知不得污染新会议。子文档分别维护模块、页面和组件实现落点。

私聊对象选择传入005，默认回复范围不由工作台当前页面推断。参与者列表不展示正在私聊、交流对象、时间或数量；创建者也无额外数据。删除状态入口只返回操作结果，不恢复会议页面或历史。
