# 实时群聊客户端设计

## 1. 工程与契约

沿用features/meetingWorkspace的API适配、chat reducer、RealtimeChatRegion、MessageTimeline和MessageComposer。只有meetingChatConnection适配文件依赖SignalR；页面/组件不直接操作生成Client。[服务端设计](../Server/design.md)是HTTP、消息和附件契约唯一来源。

## 2. 状态与恢复

每个meetingId+交流范围(public或私聊双方ID)维护messagesById、按sequence排序的ID、历史边界、highWatermark、connection generation、授权上界、草稿、待确认发送和滚动锚点。按messageId去重，序号决定显示顺序，冲突内容不覆盖原服务端事实。

活跃会议进入时先建立连接缓冲事件，订阅取得高水位，读取最新页，再afterSequence补齐缺口并合并事件。历史模式直接HTTP分页，不建立活跃订阅。before加载不当成实时缺口；重连仅补尚缺序号。切会/注销先增加generation，再取消请求和解绑连接；旧请求不能更新新会议。

membershipLeft重载权限，保留已有有权消息且暂停相关双方私聊。meetingDeleting/meetingDeleted移出会议并清理全部公开/私聊缓存、草稿和附件ObjectURL，取消请求并递增generation；删除后无历史模式。网络失败与普通404不作为本地删除完成证明。

## 3. 阅读位置

底部判断使用scrollHeight-clientHeight-scrollTop<=48 CSS px作为设计默认阈值；在底部时新消息提交后跟随。用户上滑后保存首个可见messageId及其到容器顶部的像素偏移，加载更早消息、附件尺寸变化、字体换行或实时追加后恢复同一锚点。ResizeObserver触发布局稳定后修正，不用定时刷新强制置底。

“回到最新”按钮在非底部时出现，不带未读数、催促或遗漏提示。点击后定位最后消息并恢复底部跟随。按meetingId与交流范围在当前页面内存保留锚点，切回时按该messageId加载附近页恢复；刷新默认最近页，不持久化消息正文到localStorage。图片预先给出尺寸占位，未知尺寸加载后按锚点补偿。

## 4. 发送状态

sending、pending_confirmation、saved、rejected分别呈现“发送中”“发送结果待确认”“服务器已保存”和真实拒绝原因。发送前生成一次clientSubmissionId，正文/附件/引用/visibility/recipient作为不可变待确认载荷；编辑后发新意图才生成新ID。超时先查询提交结果，saved合并原消息，确定not_found且可发送才重发；查询失败保持待确认。

HTTP响应与广播竞态按messageId合并。发送中本地占位无伪造sequence；失败保留草稿和附件暂存引用。退出后只查询结果；删除中或已删除停止内容查询与重发，并清理待发载荷。仅显示自己的提交状态，不展示接收者已读。

## 5. 编辑器与提及

输入使用参与者目录辅助插入@显示名称，记录原文UTF-16范围，不修改正文规范化。服务端mentions是最终高亮事实，按文本节点渲染。未知@或无@正常发送，无遗漏提醒或额外确认。引用只选有权消息，不能推断必须回复。

附件入口展示上传中/失败/就绪及实际大小限制；上传成功后发送消息绑定。无正文但有附件允许发送。不可预览文件提供下载。会议附件清单显示文件名、发送者、时间，支持下载和跳转原消息；跳转需按ID加载附近页并定位，不依赖该消息已在当前缓存。

## 6. 展示、安全与状态

纯文本与提及通过React文本渲染，不注入HTML；附件预览遵循服务端安全类型和独立隔离容器，文件名不可作为HTML。长文本自然换行，保留原文空白。新消息不更改浏览器标题计数。

参与者online/offline交004组件，连接诊断显示在消息区状态栏；不显示最后活跃、模型思考或阅读状态。网络失败、历史加载失败和提交失败分别提供重试，单个附件预览失败不阻塞文本阅读。按钮键盘可操作且带aria-label，移动端不因附件横向撑破布局。

## 7. 私聊选择、回复与隔离

工作台保留公开讨论入口，参与者列表或消息作者操作可打开与该参与者的私聊区域。状态键为meetingId+scope+peerParticipantId；私聊头部持续标明“私聊”和对方名称，消息标明发送者。第三人及未参与的创建者不获得该私聊的列表项、时间、数量或提示，不从公共事件推断私聊关系。进入私聊只改变本人的视图，不向全会广播动作。

点击回复私聊固定原双方及visibility；页面切换和正文@均不能改变已保存草稿/待发送载荷范围。返回公开区使用独立公开草稿；用户明确选择“公开发送”时建立新的public意图，清除私密replyTo和原附件绑定，不自动摘录原私聊。既有私聊记录不被改为公开。接口冲突按Server错误呈现，不默默转换目标。

私聊时间线、附件清单、定位、前后文均限同一双方；公开区域不自动拼入私聊引用预览。双方任一退出即暂停发送并说明原因，但仍可读已有内容；对方离线仅显示连接离线，允许留言。明确重入后重新获取双方资格，不能由打开页面恢复参与。创建者删除会议时，两类区域一并销毁，不保留私聊独立入口。

HTTP和SignalR收到的sequence为当前参与者可见投影，不能比较其他人的位置。选定scope后序号间隔可能来自本人其他有权范围，不用缺号判断丢消息；补读以服务端scope分页hasMore和高水位为准。前端过滤仅用于展示，不能替代服务端不向第三方发送数据。
