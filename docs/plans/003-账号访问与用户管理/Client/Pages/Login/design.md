# 登录页设计

## 1. 页面定位

`LoginPage` 是账号访问主题的匿名入口，负责承载登录表单、登录状态反馈和登录成功后的导航。页面不直接访问生成 API Client，不解析 Cookie，也不保存用户资料。

## 2. 进入条件与离开条件

进入条件：

- 用户访问 `/login`；或
- `AuthGate` 判断当前会话无效后导航到 `/login`。

离开条件：

- 登录成功后导航到原目标站内路径，未提供目标时导航到 `/`；
- 用户主动访问公开系统状态页时不要求登录；
- 登录失败时保持当前页面。

如果当前认证状态已经是 `authenticated`，页面应导航到经过安全校验的站内 `returnTo`，没有有效目标时导航到 `/`，不显示可再次提交的登录表单。

## 3. 页面结构

页面由以下部分组成：

1. 产品名称或简短页面标题。
2. `LoginForm`。
3. 登录失败、服务不可访问和请求中的状态反馈。

页面不展示公开注册、找回密码、修改密码或用户管理入口；用户管理只在登录后的认证布局中提供。

## 4. 交互流程

1. 用户填写用户名和密码。
2. 点击登录或在密码字段按 Enter。
3. 表单执行本地必填校验。
4. 校验通过后调用 `useAuthentication().login`。
5. 请求期间禁止重复提交，并显示进行中状态。
6. 成功后由页面执行安全导航。
7. 失败后显示统一的无效凭证或服务不可访问提示，用户名保留，密码清空。

登录失败不能说明用户名不存在还是密码错误。页面不能根据错误文案判断分支。

## 5. 状态与可用性

- 首次渲染不应因为已有会话检查而短暂显示登录表单；由认证模块状态决定显示加载、表单或导航。
- 输入控件具有明确标签和可访问名称。
- 密码输入使用密码控件，并且不写入浏览器持久化存储。
- 请求失败时保留可重试入口，不刷新页面丢失用户输入。
- 页面在窄屏下仍保持表单和错误提示可读，不依赖固定宽度。

## 6. 页面边界

页面只组合认证模块和登录表单，不承载登录验证、Cookie 操作、账号查询或用户资料逻辑。
