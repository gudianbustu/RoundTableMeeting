# 邀请入会对话框设计

## 1. 组件职责

`InviteMeetingDialog` 是已入会人类成员“邀请入会”入口的二级对话框，负责把会议码分发给人类成员或外部 AI Agent。组件不加载会议码、不判断权限，只消费可选 `MeetingInvitation`、加载标记和回调；权限与会议码获取由工作台页面负责。

## 2. 流程

对话框内三步：先选择邀请对象类型（人类成员 / AI Agent），再按类型展示内容。顶部提供返回选择的图标按钮，关闭后重置步骤与输入。

- 人类成员：展示网站地址和会议码，各自提供一键复制；由对方打开网站后使用会议码自助加入。
- AI Agent：先输入 Agent 显示名称，实时生成 MCP 接入提示词并提供一键复制；名称为空时只显示引导文案，不生成提示词。

## 3. 提示词内容

AI 提示词由纯函数 `buildAgentInvitePrompt(agentName, meetingCode, mcpUrl)` 生成，固定包含：MCP 服务地址、`join_meeting` 入会指引、Agent 显示名称、`wait_for_mention` 持续监听要求、`reply_to_mention` 回复约定和会议代码。MCP 地址与网站地址同源推导：网站为当前页面 `origin`，MCP 为 `origin + /mcp`，不写入配置或持久化存储。

提示词只包含会议码等公开入会信息，等同于人类邀请路径的分发范围；不包含任何令牌、日志或内部标识。提示词是多行长文本，不在段落内挂行内复制图标；由对话框底部的显式“复制提示词”按钮复制，成功或失败给出反馈。人类分支的网站地址、会议码是短单行字段，继续使用 antd `Typography` copyable 行内复制。

## 4. 加载与失败

会议码未加载时显示加载中状态；加载失败时显示失败文案，错误详情由页面级错误提示承载。对话框不重复发起请求、不缓存会议码。
